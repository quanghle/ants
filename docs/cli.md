# CLI and terminal UIs

The `ants` binary provides scripting commands, daemon and service subcommands, and interactive terminal interfaces (`ants chat` and `ants dash`).

## Commands

| Command | Description |
|---|---|
| `ants ask [flags] [@ant] TEXT` / `--file PATH` / `--edit` | Flags: `--thread THREAD`, `--reply-to MESSAGE` / `--forward MESSAGE` / `--forward-thread THREAD`, `--queue`, `--plaintext`, `--wait` / `-f`, `--timeout DUR`, `--attach PATH`... Send to `@ant`, else to the human's assistant while its [grant](auth.md#assistant-grant) stands, else to `system-messenger`; prints `thread <id>`, `message <id>`, `to <ant>` without `@ant` (`to pa (assistant of alice)`), and `attachment <handle>` per `--attach` file. To `@TEAM`, sends to the team's lead and prints `to LEAD (lead of team TEAM)` ([Teams](#teams)). From a human to `@HUMAN`, seals text and attached files for both humans' devices, or refuses without sendable keys unless `--plaintext` ([auth.md](auth.md#sealed-messages-between-humans)). Human messages steer a running prompt on the same thread ([architecture.md](architecture.md#pool-worktrees-and-at-least-once-retries)); `--queue` (with `--thread` or `--reply-to`) waits behind it instead. Refuses, with nothing sent, `TEXT` that @mentions two or more ants or humans other than the CLI's user: a message has one recipient, so addressing several takes `ants post`, else one message to each ([architecture.md](architecture.md#one-recipient)); with `--forward` only the note is checked. Warns on stderr if `@ant` is missing from `ants_colony`, `stale`, `unserved` (why, and when serving is tried again), `signed-out`, `failing`, or provider-limited with no fallback answering. `--reply-to` (message id or unique prefix; human creds) replies on that message's thread (`--thread` must match), addressing its author without `@ant` unless the CLI's human wrote it, and quotes a 160-character excerpt ([Quoted replies](#quoted-replies)). `--forward` (message id or prefix; human creds) sends the quoted message and its re-stored attachments to `@ant` (else assistant or `system-messenger`) on a linked new thread with optional note `TEXT` ([Forwarding](#forwarding)); `--forward-thread` (thread id, prefix or `last`) forwards a thread's kept TL;DR the same way (`ants thread tldr`). |
| `ants inbox [flags]` / `--unread MESSAGE` / `THREAD` | Flags: `--peek`, `--thread THREAD`, `--limit N`, `-f`, `--json`, `--activity`. Print unread replies (with message IDs and reactions; an ant's face before its name) and mark read across all devices (`--peek` keeps unread; `-f` streams replies, reactions added/removed to shown messages (human creds; `--json`: `{message, by, reaction, removed}`), `MAX_DELIVERIES` advisories, and, without `--thread`/`--json`, tool requests; records presence without `--thread`). Attachments show as `📎 name (size) handle` lines; `--json` gives each reference with `handle`. Reports of an assistant's acts for the human (on its activity threads, `acts-YYYYMMDD-<human>`) are left out of the listing, marked read (unless `--peek`), and summed up in one line per activity thread (`N assistant activity reports on thread T`, none with `--json`); `--activity`, or `--thread` naming an activity thread, lists them one by one. `--unread` marks unread again across all devices a message to the human and the later ones to the human on its thread, or the latest message to the human on a thread (`unread` seqs in the human's `ants_read` marker). |
| `ants colony [--json] [--team TEAM]` | List ants after each one-line avatar face such as `(ovo)` in its colour (`live`/`stale`, `idle`/`working`/`unserved`/`paused`/`signed-out`/`failing`/`rate-limited`/`out-of-quota`/`out-of-files`/`fallback`), daemon/perms versions, harness and `AGENT` (`name@version`), capabilities, `escalate_to`, workdirs, and `PROFILE`, the first 40 characters of the profile the ant wrote of itself on one line (control characters left out), plus notes on moved ants (`ants ant export --move`), version/settings drift, recovery, ants their daemon cannot serve (`unserved`: on which machine, for how long, the last error, and when serving is tried again), memory pressure, sense keeping none of an ant's data (`sense_unkept`, with why), and duplicate face/colour warnings. `--json` gives each colony entry whole, `sage`, `profile` (the ant's own words) and `sense_unkept` among its fields, and adds `born`, `avatar`, `color`, `prompts` and `sense` (the sense id) from `ants_identities` (`null` without one), and `seed`: where the face's seed comes from (`avatar` set by a human, `sense`, the record's `id`, or `name` without a record). `--team TEAM` (or `@TEAM`) lists only the ants of team `TEAM` and the teams beneath it ([Teams](#teams)). |
| `ants ant show ANT [--json] [--config FILE]` | Show one ant at a glance, matching the ant view of `ants chat`: colony entry (machine, harness, model, workdir, capabilities, escalation chain, `turn budget` (the turns a thread gets from a human's message, as the serving daemon resolves the ant's `turn_budget`), `sage`, version, `whoami`, and the `profile` the ant wrote of itself), active holds (a daemon unable to serve the ant, with why and when serving is tried again, and sense keeping none of its data, with why, among them), waiting queue, spend that UTC day, latest 10 threads, machine `config.toml` settings (secrets hidden; read afresh via `read_settings` admin order with admin creds, else as last read), shared settings (marked `NOT VERIFIED` with the reason when verification fails), latest 10 admin orders, and the ant's `team` (`backend (lead), within eng`, `none` on no team; in `--json` as `team` `{team, lead, within}`, absent on no team or a bus without `ants_teams`). |
| `ants ant avatar ANT [--seed S] [--reset] [--color C] [--auto-color]` | Print the ant's pixel-art avatar head (coloured half-blocks on a terminal, else ASCII), face, parts, colour, birth, sense id and where the seed comes from, and growth stage (`callow` < 10 prompts, `worker` ≥ 10, `veteran` with scar ≥ 100, `elder` with crown ≥ 1000). `--seed`/`--reset` and `--color` (12 hue names)/`--auto-color` update `ants_identities` via compare-and-set. Human creds. |
| `ants ant set ANT KEY=VALUE... [--no-wait]` | Change an ant's settings in `config.toml` on its machine, or in its [shared settings](config.md#shared-settings) (`whoami`, `memory`, `capabilities`, `model`, `reasoning_effort`, `context`, `fallback`, `allow`, `escalate_to`, `sage`): reads current values first (a read already pending, with none ever applied, is waited for up to 5 s rather than sent again) and sends a `set` admin order expecting those values so concurrent edits fail naming the changed field. `KEY` targets the ant's `[[ant]]` table or shared `harnesses.NAME.*`; `VALUE` is TOML (bare words read as strings, empty removes the field). Waits up to 10 s unless `--no-wait` ([auth.md](auth.md#admin-orders)). Admin device creds. |
| `ants ant pause ANT [--machine M] [--wait DUR]` | Pause an ant via admin order (`paused = true`): stops pulling new prompts while running prompts finish and harnesses stay live ([config.md](config.md#pausing-an-ant)). Waits `--wait` (default `10s`). Admin creds. |
| `ants ant resume ANT [--machine M] [--wait DUR]` | Resume a paused ant via admin order, removing `paused` so queued messages run in turn. Admin creds. |
| `ants ant memories ANT [--json] [--machine M]` | Read an ant's memories via `read_memories` admin order while its daemon is online: core memories (`whoami`, `memory`, `tasks`), read-only size-capped harness `memory_files` ([config.md](config.md#memory-files)), `BD_DB` memories, and the provider's memories view under `memories of provider NAME` (`provider` in `--json`; provider errors noted, not fatal). Built-in sense shows identity, `growth report`, persona (with pending proposal), self-model, relationship records, skills, last dream, read-only open work (`open findings`, `open commitments`, `active reminders`, `open tasks`, ≤ 20 each), and core and top memories (`no sense data` when empty; [sense.md](sense.md#what-an-operator-sees-and-configures)). Admin device creds. |
| `ants ant mcp ANT [--json] [--machine M] [--sign-in SERVER [--callback URL]]` | Show the MCP servers of `ANT`'s harness and each one's status (`connected`, `pending`, `needs_auth`, `failed`, `disabled`), tools and source via `read_mcp` admin order while its daemon is online; the daemon opens a probe session of the harness for it. Protocols `claude`, `codex` and `copilot-sdk` report them; other protocols (`acp`, `antigravity`) do not. `--sign-in` starts the harness's OAuth sign-in to `SERVER` via `mcp_sign_in` and prints the address to open in a browser; a browser on another machine than the ant's ends on a loopback address that fails to load, which `--callback URL` hands over. The harness stores the credentials; running harnesses may need `ants ant restart ANT`, except open `copilot-sdk` sessions listing the server in `mcp_sign_in` ([config.md](config.md#copilot-sdk-protocol--copilot-sdk)), which are told once it connects ([auth.md](auth.md#admin-orders)). Admin device creds. |
| `ants ant sense-id ANT [--take SIDE] [--config FILE]` | Print the sense id the ant's home here keeps and the one its identity record names; while they differ its daemon refuses to open sense. `--take home` names the home's in the record (compare-and-set), `--take record` has the home keep the record's; the other id's data stay in the log, and the daemon opens sense under the settled id when next used. Refused where data would be lost: `record` while writes wait in the home to be appended to the log, either while the home's sense data await their import. Runs where the config file lists the ant. Human creds. |
| `ants ant export ANT [-o FILE] [--move] [--config FILE] [--no-provider]` | Export an ant to a plain JSON file (default `./ANT.ant`, mode `0600`, never overwritten): identity record, verified shared settings (or config settings with a warning), and home memory files packed between prompts ([config.md](config.md#exporting-and-importing-an-ant)), and the export of the ant's provider when it exports (the built-in sense's: the ant's sense log and skill files under a manifest of SHA-256 hashes, [config.md](config.md#senses-part)), through an `export_provider` admin order to this machine's daemon (admin device creds; failing fails the export, `--no-provider` leaves it out). `--move` marks the ant moved so daemons drain and stop serving it. Human creds. |
| `ants ant import FILE [--as NEW] [--no-provider] [--provider-only] [ants add flags]` | Import an exported ant: create its identity record (refused on name or id collision, and, as `ants add` refuses them, for a name a team or a human holds), append `[[ant]]` to `config.toml` (CLI flags override exported settings), issue a new key, and restore memories into an empty home with no tasks. `--as` renames while keeping id, avatar, and growth. A provider's export in the file goes to the ant's provider through an `import_provider` admin order to this machine's daemon (admin device creds), only for a provider of the same name; sense takes its part in under the same sense id once its hashes and log chain verify, keeping the ant's sense data closed until then. When that fails the import warns why, and `--provider-only` retries that part alone for an ant already imported. `--no-provider` leaves it out. Human creds. |
| `ants ant unseal ANT` | Clear the `moved` mark set by `ants ant export --move` so daemons serve the ant again. Human creds. |
| `ants ant orders ANT [--json]` | List admin orders to `ANT` across machines, oldest first (`pending`, `held`, `applied`, or `refused` with reason; `<human> via <assistant>` for assistant orders) ([auth.md](auth.md#admin-orders)). Human creds. |
| `ants ant restart ANT [--now] [--machine M] [--json]` | Order the serving daemon to restart `ANT`'s harnesses: idle ones stop immediately, working ones after their prompt or cancelled immediately with `--now`; next prompts resume sessions in fresh processes ([auth.md](auth.md#admin-orders)). Admin device creds. |
| `ants ant stop-trail ANT RUN [--machine M] [--wait DUR]` | Stop a [trail](trails.md) run `ANT` conducts (its id or a unique start of one among `ANT`'s runs, as `ants trail runs --ant ANT` lists them) via `stop_trail` admin order: the serving daemon stops it as `ants trail stop` has the conductor do; while that daemon is away the order waits in the stream and applies once it is back. Prints the steps still waiting in other ants' queues, each with `ants withdraw ANT MESSAGE`. Refused for a run that ended. Waits `--wait` (default `10s`), else tells the order is pending ([auth.md](auth.md#admin-orders)). Admin device creds. |
| `ants ant resume-trail ANT RUN [limit-flags] [--machine M] [--wait DUR]` | Resume a stopped trail run `ANT` conducts, or one failed on a limit, via `resume_trail` admin order, as `ants trail resume` has the conductor do; limit flags (`--steps N`, `--at-once N`, `--turns N`, `--wall DUR`) replace those of the run's limits they name (within the same maxima), a flag left out keeping the run's own. Refused at once, without an order, for a run its record shows done or failed otherwise. The order waits for a daemon away, as `stop-trail`'s does ([auth.md](auth.md#admin-orders)). Admin device creds. |
| `ants ant add NAME --on MACHINE [settings] [--wait DURATION]` | Add an ant remotely by [admin order](auth.md#adding-and-retiring-an-ant-by-order): the machine's daemon generates the key, `ants signer` signs it, credentials and `[[ant]]` are written, and the ant starts (`/add` in `ants chat`). Admin creds; `ants signer` running. |
| `ants ant retire ANT [--machine M] [--wait DURATION]` | Retire any config-listed ant by admin order: table removed, ant drained, key revoked by `ants signer`, credentials deleted, home kept, and leaf uplink shrunk (`X` in `ants chat` ant view). Admin creds; `ants signer` running. |
| `ants ant clone SRC NEW [settings] [--machine M] [--wait DURATION]` | Clone `SRC` to `NEW` on `SRC`'s machine by [admin order](auth.md#cloning-an-ant-by-order): pauses `SRC`, copies home, thread histories, worktrees (`ants/NEW/<thread>` with uncommitted changes), and `[[ant]]` settings, forks or seeds sessions, signs `NEW`'s key via `ants signer`, and resumes `SRC` (`/clone` in `ants chat`, `C` in its ant view). Admin creds; `ants signer` running. |
| `ants machines [ANT] [--json]` | List machines recorded in `ants_machines` (machine, host name, version, timestamp, ants) plus the account-key holder `_account`; with `ANT`, list machines serving it, latest first. Human creds. |
| `ants spend [ANT] [--thread THREAD] [--days N] [--json] [--config FILE]` | Report token and cost spend over UTC days (default 7, max 366) or on a thread, since a human's last message there and in all, against local config caps ([config.md](config.md#spend-report)). |
| `ants notes THREAD [--attach PATH]... [TEXT] [--json]` | Show thread notes with attachments, or post `TEXT` (with `--attach` files) as the CLI human (resets budget to 8 turns; wakes nobody). `--json` prints one `NotesPost` a line with `by` naming its author as the text does (the post made, with `TEXT`). |
| `ants react MESSAGE REACTION [--remove]` | Add or remove a reaction (`1–64` of `a-z0-9-`); wakes nobody, marks nothing read, ends no wait. `MESSAGE` is a message id or (for humans) a unique prefix. With ant creds, `ants signer` applies the change for messages the ant reads. |
| `ants answer MESSAGE PICK...` | Answer an ant's `ask_human` questions in one message, a pick for each in order: option `N`, `N,M` (where several may be picked) or (when allowed) typed text, quoted when several questions are asked (`ants answer 0193 2 1,3 'after lunch'`); a lone question takes every word (`ants answer 0193 not before Friday`). A typed answer @mentioning two or more ants or humans is refused, as for `ants ask`. Prints `thread <id>` and `message <id>`. Human creds. |
| `ants post [flags] CHANNEL TEXT` / `--file PATH` / `--edit` | Flags: `--thread THREAD`, `--reply-to MESSAGE`, `--queue`, `--wait` / `-f`, `--timeout DUR`, `--attach PATH`... Post to `ops` or `'#ops'`; prints `thread <id>`, `message <id>`, and `attachment <handle>` per `--attach` file (`@ant` wakes members, `@human` notifies members, `@team` wakes the team's lead, a member, and is refused otherwise ([architecture.md](architecture.md#channels)), no mention triages). `--reply-to` replies to a message or post on its thread, quoting it, as for `ants ask`; a post being replied to must be in `CHANNEL`, and the mentions in the text still pick whom the post wakes. `--queue` (with `--thread` or `--reply-to`) waits behind a prompt running on the thread rather than steering it, as for `ants ask`. |
| `ants channel create` / `set` / `add` / `remove` / `list` / `delete` | Manage channels (`--member USER,...`, `--messenger ANT`, `--default-messenger`, `--owner ANT`, `--no-owner`, `--description TEXT`, `--no-description`); a team is refused as a member, the messenger or the owner: `@TEAM` in a post mentions its lead. A description (up to 1000 characters without control characters but whitespace or characters reordering text, human credentials only) opens each member ant's new session on a thread of the channel; `list` shows it in a `DESCRIPTION` column when a channel has one. For human members, `list` includes `UNREAD` counts: the posts the human's notify level of the channel counts, `@M` mentions, and the other unread posts apart (`N (@M) +K other`). `list --json` prints one `ChannelEntry` a line, with `unread` (`posts`, `mentions`, `other`) where counted. `/channel create` / `set` / `add` / `remove` / `delete` in `ants chat` do the same ([command bar](#ants-chat-command-bar)). |
| `ants team create TEAM [--lead ANT] [--member NAME]... [--owner HUMAN] [--description TEXT]` / `set TEAM [--lead ANT \| --no-lead] [--owner HUMAN \| --no-owner] [--description TEXT \| --no-description]` / `add TEAM NAME...` / `remove TEAM NAME...` / `delete TEAM` / `list [--json]` / `show TEAM [--json]` / `repair [--apply]` | Manage [teams](#teams) in `ants_teams` (changes need human credentials). `create` names the lead, an ant that becomes the team's first member (without `--lead`, the team takes the lead of the nearest team above it with one), and further members (ants with an identity record, or teams); `add PARENT TEAM` puts a team beneath another; `set --no-lead` leaves a team without a lead of its own, and `remove` of the lead does too. `list` prints the forest (`TEAM`, `LEAD`, `MEMBERS`, `OWNER`, and `DESCRIPTION` when a team has one), each team indented under the team holding it, `--json` one object per team with its `parent`; `show` prints the team, the teams above it, its lead (`X (from team Y)` for one taken from above, `none` with none above either) and owner, and its members as a tree with each ant's face and colony state, the lead marked `★ lead`, `--json` one object with the members as a `tree`; `repair` shows each rule a directory breaks and `--apply` writes it repaired ([teams](#teams)). |
| `ants channel notify CHANNEL [LEVEL]` | Show or set the human's notify level of a channel, across all its devices (`ants_notify`): which unread posts count in `ants chat` and `ants channel list`, the others showing apart and dim. `all` counts every post, `humans` (the default) posts by humans and those mentioning the human, `mentions` only those mentioning the human. Mentions still reach the human's inbox at every level. Human credentials only. Without `LEVEL`, `--json` prints `{channel, human, level}`. |
| `ants channel read CHANNEL [--thread THREAD] [--limit N] [--archived] [--peek] [--json]` | Print channel posts grouped by thread with attachments (threads whose opening post is no longer kept first, then in the order they started), leaving out the human's archived and `auto-archived` threads unless posted on since (`--archived` prints only those); marks printed posts read across human devices unless `--peek`. `--thread` reads from the time in a time-ordered thread id on (else every post kept); `--limit N` reads back from the latest posts only as far as N of the threads printed started. `--json` prints one `ChannelPost` a line in the same order, with `by` naming its author as the text does. |
| `ants channel serve` | Run the channel manager (`ants auth channel-manager` creds) to apply owner `manage_channel` requests and an assistant's `describe_channel_for_human`. |
| `ants auth builtin messenger` / `sage [--js-domain DOMAIN]` | Issue credentials for `system-messenger` or `system-sage`. Run on the machine holding the [account keys](auth.md). |
| `ants thread list [flags]` | Flags: `--ant USER`, `--owner HUMAN`, `--grep TEXT`, `--escalated`, `--pinned` / `--archived`, `--since DUR`, `--limit N`, `--json`. List active threads within `--since` (default `24h`, `0` all; limit 50), pinned last, archived and `auto-archived` hidden unless `archived+new`, `done` in STATE. |
| `ants thread show THREAD [--since DUR] [--json] [--no-tools]` | Print a thread's stored messages, posts, notes, escalations, tool requests/decisions, dead letters, attachments, questions/answers, and reactions under a title/done/mark header. Each message is a `● <from> -> <to> · <time> · message <id>` line (its kind, note and answer after the route when there are any) with its text indented under it. Timeline entries follow as `⎿` lines: tool calls as `<time> <ant>  Name(args) · <duration>` (or `failed after <duration>`, `in progress`), rejected or expired tool requests with the tool, request id and outcome (including the decider and assistant when recorded; kind `rejected` in `--json`), `no reply` lines for turns that sent no reply, and an `ended:` line for each run of a prompt: how it ended (`replied`, `no reply`, `cancelled`, `cut by a cap`, `failed`), its duration, and when reported the tokens, US-dollar cost, its tool calls by ACP kind with how many failed (`calls execute 3 (1 failed), read 2`), its calls of the built-in sense's tools, the tool requests it asked and whether its session was rebuilt (kind `ended` in `--json`, its measures under `ended`). `--no-tools` omits the timeline's tool calls and rejections, not stored requests, decisions, `no reply` or `ended:` lines. A quoted reply starts with `↪ replying to <author>: <excerpt>`. |
| `ants thread search [flags]` | Flags: `--grep TEXT`, `--from USER`, `--to USER`, `--channel NAME`, `--type KIND,...`, `--since TIME`, `--until TIME`, `--limit N`, `--json`. Search stored messages across threads matching all filters (latest `--limit`, default 50, oldest first). |
| `ants thread title THREAD [TEXT...] [--clear]` | Print, set (1–120 chars, shared across humans), or clear a thread title; sealed for both humans' devices on sealed DM threads. |
| `ants thread done` / `undone THREAD` | Mark a thread done or clear its done state for every human; a later message, post, or note reopens it. |
| `ants thread pin` / `unpin` / `archive` / `unarchive THREAD` | Pin or archive a thread for the CLI human across devices (mutually exclusive; unarchiving an `auto-archived` thread keeps it another `auto_archive` period). |
| `ants thread tldr THREAD [--new] [--json]` | Print the thread's stored TL;DR while current, else ask `[cli]` `summary_ant` for one (≤ 120 words) and store it ([config.md](config.md#catch-up-summaries)). |
| `ants digest [--since DUR]` | Ask `[cli]` `summary_ant` for a digest of threads active within `--since` (default `24h`, `0` all); stored nowhere. |
| `ants thread mute` / `unmute THREAD [--for DUR]` | Mute push notifications for `THREAD` across devices (default `30d`, max `365d`), or unmute ([webhooks.md](webhooks.md#quiet-hours-snooze-and-muted-threads)). |
| `ants trail save FILE [--name NAME]` | Save the [trail](trails.md) of a `.py` file for the colony in `ants_trails`, under its meta's `name` or `--name` (1–64 of `a-z0-9-`, not starting with `-`; a UUID is refused, as `ants trail show` reads one as a run's id), with the human and time that saved it. The file is checked, not run: it must compile (a syntax error prints the traceback with its line) and start with its literal `meta`, each of its meta's `waypoints` naming a top-level `async def` taking one state, with no steps at its top level. Replaces a saved trail of the same name, an ant's included (ants save theirs with the `save_trail` tool), and says whose it replaced, the human becoming its saver. Human creds. |
| `ants trail list [--json]` | List saved trails with description, phases, waypoints (a column shown when a trail has any), [ratings](trails.md#rating-and-finding-trails) (columns `RATINGS`, as worked/partly/failed, and `LATEST`, the latest reason, shown when a trail has any) and source: the colony's (`colony`, saved by whom, a human or `ant NAME`, and when, and in a FROM RUN column shown when a trail has one, the run an ant saved it from), then this machine's `~/.ants/trails/*.py` that pass the same check, each named by its file name less `.py` as a conductor's daemon finds it (files failing the check, or whose name is no trail name, are skipped with a warning). A local trail sharing a colony trail's name is marked `(the colony's runs)`: the colony's trail is the one a run of that name runs. `--json` prints one object per trail (`source` `colony` or `local`, a colony trail's `saved_by` `{kind: human\|ant, user}`, `saved_from` when an ant saved it from a run, `shadowed` when marked, and `ratings` `{worked, partly, failed, latest}` of a trail rated, `latest` its 3 latest ratings). |
| `ants trail show NAME` / `RUN [--json] [--follow]` | With a trail's name, print its meta, source (who saved it, and the run an ant saved it from), its ratings (counts, then the 3 latest, each with its outcome, run, conductor, age, task and reason) and script, the colony's before a local one of the same name (and which local file it takes precedence over). ### Text written by others

Without `--json`, the commands print what other humans and ants wrote (messages, posts, notes, questions, titles, TL;DRs, channel descriptions, dead letters, `ants watch` traffic) without control characters but line breaks, and without characters reordering text (U+061C, U+200E, U+200F, U+202A–U+202E, U+2066–U+2069), so no escape sequence reaches the terminal; tabs print as spaces. `--json` prints it as stored.

### Thread and message identifiers

`THREAD` in `ask`, `inbox`, `post`, `notes`, `thread show`, `thread title`, `thread pin`/`unpin`/`archive`/`unarchive`, `thread done`/`undone`, `thread mute`/`unmute`, `cancel`, `watch`, `spend --thread`, and `channel read --thread` accepts a hyphenated UUID (used without lookup), a unique prefix (or non-UUID thread ID), or `last` (latest thread the human sent or received on). Prefix lookup (human creds only) checks the human's own threads from the last 7 d first, then all threads in the last 7 d (bounded to `[-5m, +10m]` around the timestamp encoded in a UUIDv7 prefix); exact matches win, and ambiguous or missing prefixes list candidates (id, time, title where readable, route, and first line of the latest message).

### Quoted replies

A quoted reply (`ants ask --reply-to`, `ants post --reply-to`, or `>` in the `ants chat` thread view) names the message it replies to in `in_reply_to` and carries `quote`: that message's author and its text with whitespace collapsed, cut at 160 characters with `…`. The daemon starts the prompt for it with `[ants] In reply to <author>: "<excerpt>"`, since the ant may not hold the message (another ant wrote it, or it is from an earlier session). `ants thread show` and the thread view show `↪ replying to <author>: <excerpt>` above its text. Between humans, the quote is sealed with the text. A sealed message's excerpt never goes in the clear: a reply quoting one that is not sealed itself (to an ant, a channel post, or `--plaintext`) carries only the author, shown as `↪ replying to <author>` and prompted as `[ants] In reply to a sealed message from <author>.`. The CLI reads the message back with the human's credentials to quote it (a message kept over the last 7 days), so a sealed message that does not open on the device cannot be quoted.

### Teams

A team, kept in `ants_teams` ([architecture.md](architecture.md)), has a lead, an ant among its direct members, or, without a lead of its own, takes the lead of the nearest team above it with one; and it has members: ants and other teams, each on at most one team, so the teams make a forest. Team ids share the names of ants and humans: `ants team create` and a lead's `manage_team` refuse the name of an ant (one with an identity record), a human or a reserved name, and every way an ant or a human gets its name refuses the name of a team, when the hub answers within a few seconds: `ants add`, `ants auth user`, `ants ant import` (with `--as` too), `ants signer` signing an admin's add or clone order (`ants ant add --on`, `ants ant clone`, `/add` in `ants chat`) or a manager's `request_ant`, and a registration (`ants login`). A human's name is the human's whatever the directory holds: `ants ask @NAME` and `ants chat` send to the human. A human is no member, at most a team's `--owner`.

- `ants ask @TEAM TEXT` sends to the team's lead, its own or the nearest above it, carrying the team in the envelope's `team`, and prints `to LEAD (lead of team TEAM)`; a team with no lead, nor any above it, is refused.
- A retired ant (`ants retire`, `ants ant retire`, a manager's retirement) or a revoked one (`ants auth revoke NAME`) leaves its team, and its channels ([architecture.md](architecture.md#channels)); a lead leaving leaves the team without a lead of its own, so that it takes the lead of the nearest team above it with one. A team with no lead, nor any above it, refuses messages, and `ants doctor` warns of it, until a human names one (`ants team set TEAM --lead ANT`). When the directory cannot be changed, the command says so and names `ants team remove TEAM ANT`.
- A directory breaking the rules (written by hand or by an older writer) cannot be read or changed by `ants team`, `ants chat` or the daemons, and `ants doctor` fails naming `ants team repair`. `ants team repair` prints each rule it breaks, a line each; `--apply` writes it repaired by compare-and-set, read and repaired again while another writer changes it meanwhile, and tells each team it changed on the human's status. The repair goes in directory order, the order teams were created and members added: a team listed again loses its later entry, whose members are then on no team; a member listed twice in a team, or on several teams, stays where it came first, in the team that comes first, and leaves the others; a team holding itself, directly or through its member teams, has the team of the cycle that comes first leave the team holding it, so that it is a top-level team; a lead no longer a direct ant member of its team is cleared; a description over 1000 characters is cut. A directory that is no JSON a team directory reads is not repaired: deleting key `directory` of `ants_teams` starts it over.

### Forwarding

`ants ask --forward MESSAGE`, and `f` or `/forward @ant [TEXT]` in the `ants chat` thread view, hand a message to another user on a new thread; `ants ask --forward-thread THREAD`, and `f` on a home item or a work thread, hand a thread by its kept TL;DR. A team named as the recipient, in either, hands it to the team's lead carrying the team, as a message to a team does ([architecture.md](architecture.md#teams)), and a team with no lead in it nor above it is refused with nothing sent. The new thread's first message holds the note, if any, then `Forwarded from <author> on thread <id>, <time> UTC:` and the message's text quoted line by line, with a `📎 <name> (attached)` line per attachment; the attachments are read with the human's credentials (opened when sealed on a message that opens on the device) and stored again under the new message, for its recipient. With no message selected in the thread view, or a thread selected elsewhere, `/forward` carries the thread's TL;DR instead (`Forwarded thread <id>, its TL;DR by <ant>, <time> UTC:`), refusing until one is kept (`S` or `/tldr` asks for one). The message links to the source thread (`origin_thread`), as a message an ant spins off a thread does, so `ants chat`'s delegation tree of the source thread shows the new thread, labelled `forwarded:` where a thread an ant spun off shows `spin-off:`. The recipient gets only what is forwarded: no access to the source thread or its other messages comes with it.

## Identity, setup, completions and doctor

- **Connection & identity:** every command accepts `--nats`, `--creds`, and `--js-domain` (and `--help`, listing its flags), falling back to `[cli]` then top-level keys in `ANTS_CONFIG` (`~/.ants/config.toml`), except `ants daemon` and `ants add` (which read top-level config directly). NATS URLs containing credentials or tokens are rejected. Without credentials the CLI acts as the human `ANTS_HUMAN` names, else `[cli]` or top-level `human`, and fails naming that key when none is set. Connecting as a human ensures `ants_humans` contains `<name>` and runs an `ants init` pass creating missing objects and denying rollups on those allowing them. Ant credentials skip `ants_humans`, warn, refuse `ants inbox`, and leave `--wait`/`-f` replies unread.
- **`ants setup`:** without `--harness` and an existing config file, chooses the harness of a new config by looking up each built-in's command on `PATH` (no handshake): a single installed harness is picked and reported, multiple are offered in a numbered terminal prompt (failing without a TTY), and none installed fails with install and sign-in commands ([config.md](config.md#choosing-a-harness-in-ants-setup)). Setup then idempotently writes `~/.config/ants/nats.conf` (JetStream in `~/.ants/jetstream`, skipped for non-loopback `--nats` or existing `leaf.conf`), downloads the pinned nats-server into `~/.ants/bin` when the service or `--managed-nats` needs one and neither `--nats-server` nor a nats-server beside `ants`, in `~/.ants/bin` or on `PATH` is found ([operations.md](operations.md#bundled-nats-server)), installs/starts `ants.nats` / `ants-nats`, runs `ants init`, creates/appends `~/.ants/config.toml` (a new file names the default human `human`: `--human NAME`, else the CLI's human, else the login name), runs `ants harness check`, issues host credentials when ants have credentials and account keys are local ([auth.md](auth.md#machine-host-credentials)), installs/starts/reloads `ants.daemon` / `ants-daemon`, installs shell completions, and runs `ants doctor --no-harness` (`--dry-run` previews without changes). `--managed-nats` (loopback `--nats` only) installs no NATS service: a new config file gets a [`[nats_server]`](config.md#managed-nats-server) table naming `leaf.conf` when present, else `nats.conf` (with `command` from `--nats-server`), the daemon service is installed or restarted, and `ants init` runs once the daemon's server listens (`--no-services` prints `ants daemon --config FILE` instead). With `--no-services`, a local server not listening yet fails no check of the closing `ants doctor`: its `server` and `leaf node` checks are skipped, naming the command that starts it (`ants daemon --config FILE`, or `nats-server -c FILE` without `--managed-nats`), and `ants doctor` checks it once it runs. It fails while an `ants.nats` / `ants-nats` unit is installed for that configuration, printing the commands that remove it, or, for a new config file, while a server listens on the address already; an existing config file is not edited, and without the table its step fails naming the line to add and the daemon restart to run. `--web` (loopback `--nats` only) appends a `websocket` block to `nats.conf`, the one file a re-run adds to: a loopback listener on port 4281 taking only pages of `http://127.0.0.1:4280`, the origin `ants web` serves, and restarts a server running the file (its service, or the daemon managing it), as `nats-server` reloads no WebSocket change; a second run reports the listener as existing and changes nothing, a block naming other origins is kept and fails the step, and with a `leaf.conf` the step fails naming `ants leaf config --web` ([transport.md](transport.md#pages-on-a-single-machine-or-a-leaf-node)).
- **Shell completions:** `ants completions --install` writes to `~/.local/share/bash-completion/completions/ants`, `~/.local/share/zsh/site-functions/_ants` (add to `fpath` before `compinit`), or `~/.config/fish/completions/ants.fish` (`XDG_DATA_HOME`/`XDG_CONFIG_HOME` honoured). Dynamic lookups (`ANTS_COMPLETE`, 2 s timeout, silent on error, skipped for OS-keystore seeds) complete `@ant` / ant names, channels, `last` + recent 7 d threads (with thread `title`, else latest line), the latest 50 messages to or from the CLI human over 7 d matching the typed prefix and suggested reactions on `ants react`, pending tool requests, and dead-letter sequences.

## Ant flags

The `[ant-flags...]` of `ants daemon` and `ants add`, and the settings of `ants ant add`, describe one ant: each is the `[[ant]]` key of [config.md](config.md) with dashes for underscores, and takes the values of that key. With `ants daemon --config FILE --ant NAME` a flag overrides the key of that ant in `FILE` ([config.md](config.md#precedence-and-reload)), `--allow` adding to its `allow`.

- **One value:** `--workdir`, `--home`, `--whoami`, `--memory`, `--tasks`, `--harness`, `--human` (an ant described by flags takes the file's top-level `human` without it), `--model`, `--reasoning-effort`, `--context`, `--approval-timeout`, `--max-harnesses`, `--idle-timeout`, `--prompt-timeout`, `--max-tool-calls`, `--max-thread-tokens`, `--max-thread-cost`, `--max-daily-tokens`, `--max-daily-cost` and `--spend-warn-percent`.
- **Repeatable:** `--env NAME=VALUE` (an entry of `env`), `--allow RULE` (an entry of `allow`) and `--capability TAG` (an entry of `capabilities`, also as a comma-separated list).
- **Switches:** `--allow-tools` (the same as `--allow '*'`), and `--worktrees` or `--no-worktrees` for `worktrees = true` or `false`.

## Composing and waiting

- **Input:** `ants ask` and `ants post` take trailing words joined by spaces, `--file PATH` (`--file -` reads stdin; preserves internal formatting, strips BOM and trailing newlines), or `--edit` (`$VISUAL` -> `$EDITOR` -> `vi`/`notepad` on a `0600` temp file; empty/blank messages abort). A message (`ants ask`, `ants post`, `ants notes`, and those sent from `ants chat`) over the server's `max_payload` less 1 KiB for headers is refused before anything is stored, naming its size and the limit: longer text goes in a file sent with `--attach` (`/attach` in `ants chat`).
- **Attachments:** `--attach PATH` (repeatable; `ants ask`, `ants post`, and `ants notes` with `TEXT`) attaches up to 8 regular files of at most 8 MiB each, named by base name (without `/`, `\`, control characters or characters reordering text) and typed by extension (`application/octet-stream` otherwise). Files are stored in `ants_files` before sending; any failure sends nothing. An attachment's id derives from its name, type, bytes and the hour it is made in, so the same file sent again within that hour, after a full store refused part of it, reuses the chunks already stored rather than pinning a second copy for the store's 30 days (a sealed attachment, whose ciphertext differs on every try, excepted). Each attachment gets a handle `<sender>.<inbox|notes|chan>.<target>.<id>` accepted by `ants attachment get`.
- **Sealed messages:** messages between two humans are sealed end to end for their devices' keys in `ants_devices` and any device-enrolled assistant (`ants assistant seal on`), unless `--plaintext` is set. Readers print opened text, looking up newly enrolled sending devices on demand, else `[sealed]` (no key for this device) or `[forged]` (decryption/sender failure); `--grep` matches opened text only, and `ants watch` and dead letters show `[sealed, N bytes]` ([auth.md](auth.md#sealed-messages-between-humans)).
- **Waiting:** `--wait` prints the first reply and exits `0` (`--timeout` exits `1` on timeout; Ctrl-C exits `130`); `-f`/`--follow` streams replies until `--timeout` or Ctrl-C (`0`), marking printed replies read, plus live reaction changes on the sent message and printed replies (human creds). On a terminal with human credentials, stderr displays an in-place status line (`not served`, `queued behind N`, `working`, `thinking`, `writing`, `running <tool>`, `waiting for approval` with `ants tools approve <ant>/<id>`, `harness signed out`).

## Threads, search, titles, done states and marks

`ants thread list`, `show`, and `search` read `ANTS` with human credentials via batched direct gets (`$JS.API.DIRECT.GET.ANTS`, 256 messages/request), consuming and marking read nothing. Entry kinds: `message`, `escalation`, `mention`, `post`, `note`, `approval`, `decision`, `dead` (subject mismatches marked `(forged)`).

- **Search (`ants thread search`):** combines `--from`, `--to`, `--channel`, `--type`, `--grep` (case-insensitive), `--since` (inclusive, default 24 h before `--until`), `--until` (exclusive, default now; accepts durations, RFC 3339, or UTC `YYYY-MM-DD[ HH:MM]`), and `--limit` (default 50). `--from`, `--to`, and `--type` prune scanned subjects server-side.
- **Titles (`ants thread title`):** 1–120 trimmed single-line chars, without control characters or characters reordering text (U+061C, U+200E, U+200F, U+202A–U+202E, U+2066–U+2069; left out of titles read back as well), stored at `title.<thread>` in `ants_threads`, shared across humans and shown in `thread list`, `thread show`, `ants chat`, and tab completion. An ant's suggested title (`suggest_thread_title`, carried on its reply) is stored by the next human `ants thread list` or `thread show` via CAS only if `title.<thread>` has no entry and no delete marker (`(suggested by <ant>)`). On threads carrying sealed messages between two humans, `ants thread title` seals the title for both humans' devices (`[sealed]` elsewhere) and ignores ant suggestions ([auth.md](auth.md#sealed-messages-between-humans)).
- **Done (`ants thread done|undone`):** shared state at `done.<thread>` in `ants_threads` (`ThreadDone {thread_id, by, at, after}`); changes no ant's work, reply, or notification, but ends the [escalation reminders](architecture.md) of an escalation marked done after, and the daemon of each ant holding a session of the thread tells the ant's provider (`thread_done`, [lifecycle events](architecture.md#lifecycle-events)). Any message, channel post, or note stored above `after` reopens the thread at read time without a write (tool requests, decisions, and dead letters do not). `ants thread undone` writes a 30-day delete marker so [review packets](sense.md#dreams) can distinguish an explicit undo from a thread never marked done.
- **Pins & archives (`ants thread pin|unpin|archive|unarchive`):** per-human CAS state at `marks.<human>` in `ants_threads` (mutually exclusive). Pinned threads sort last and survive `--limit`; archived threads hide from `ants thread list`, `ants dash`, `ants channel read`, and `ants chat`'s work, the `all` tab of channel views (their `archived` tab lists them), DMs and their unread counts (as do `ants channel list`'s) until new messages arrive (`archived+new`).
- **Auto-archive (`auto_archive` in `[cli]`):** off by default; with e.g. `auto_archive = "14d"`, an unpinned, unarchived thread with no entry stored for that span counts at read time as `auto-archived` (`auto_archived` in `--json`) and hides like an archived thread until a new entry arrives. `ants thread unarchive` stores a `kept` timestamp in `marks.<human>` for one more `auto_archive` idle period.
- **TL;DRs and digests (`ants thread tldr`, `ants digest`):** requested from `[cli]` `summary_ant` on dedicated summary threads hidden from thread lists, the inbox, and push notifications; see [config.md](config.md#catch-up-summaries).
- **Pruning:** `ants thread list` prunes marks, titles, TL;DRs, and done states of threads with no message remaining in `ANTS` (30 d retention + 30 d outbox grace), using CAS and revision-conditioned deletes with 1 s TTL delete markers.

## Terminal UIs and reactions

### `ants chat`

`ants chat [--since DUR] [--compact]` (also bare `ants` on a TTY; human creds, default `--since 7d`) opens the full-screen terminal chat UI. A notice shows there for 15 s, cut at the width with `…`, as the command bar's status line is; an error begins with `✗` besides its colour and stays, wrapped over three lines at most, until a key is pressed. `N` lists the notices of the run, the latest first, each in full with its local time (`↑↓`/`j`/`k`, `PgUp`/`PgDn` and `Home`/`End` scroll; `Esc`, `q` or `N` closes). With no thread read, home lists what can be typed: `@ant` and a text to ask an ant, `#channel` and a text to post, `Ctrl-K` and a text for the assistant or the messenger, and `?` for the keys. In the lists and the thread view, a bar at the left of each of its lines marks the selected item (coloured in the focused view, dim otherwise; without colour under `NO_COLOR`) and its first line is bold; tables and tabs mark the selected row in reverse video.

- **Navigation & header:** the header shows the human, server, the place shown (on a thread, its channels and title) and connection state: `● connected`; `○ disconnected <time>, reconnecting` while the NATS server is lost; or `○ hub out of reach <time>, retrying` while the server is connected but the hub's JetStream does not answer through it, as on a machine whose leaf node's uplink is down.   - *Queue & summary:* the top line counts changes since the previous device session (`chat-state.json` beside `config.toml`, else 24 h; also stores `T` mode, channel tabs, and `Ctrl-O`/`Ctrl-\` folds) plus UTC-day spend (`s` opens/refreshes the digest overlay; `j`/`k`, `PgUp`/`PgDn`, `Home`/`End` scroll it within its rows, `s` asks again, other keys close it).   - *Inline tool & question cards:* tool cards wrap up to 6 lines (fewer on short screens), name what `A` allows (`A always: …`), and group same-ant/thread pending requests (`Enter` expands/collapses the group). `a`/`A`/`r` decide `allow_once`/`allow_always`/`reject` inline when the request fits whole, else open full details (`Enter` always opens full details: command text, file path/content, or indented JSON; `↑↓`/`PgUp`/`PgDn` scroll; settled cards linger 2 min unless decided locally). `n` opens the bar to reject with a note (`ants tools reject --note`; a refused rejection sends nothing and restores the note). On a group, `l` asks in the footer to allow once each of its requests of the oldest's tool kind (`l allow 3 execute` on the card), and `y` confirms: they are allowed once in turn, oldest first, as `ants tools approve` does, never always; one line then tells how many were allowed, answered already elsewhere or failed. One decision or allow-all is stored at a time. Question cards answer immediately on `1`–`9` or focus on `Enter` (`↑↓` move, `Space`/digit toggles `[x]` for multi-select, last row types free text or opens `/answer `, `Esc` leaves; multi-question cards show per-question tabs `←`/`→`/`Tab` plus `Submit`). A card answered here shows `answer sent` and takes no further answer until the answer is read back; a failed answer makes it answerable again.
  - *Thread actions on home:* `g` grants fresh turns (`Carry on`), `r` replies/follows up, `f` forwards the thread's TL;DR ([Forwarding](#forwarding)), `x` cancels a running prompt, `d` marks done (and marks inbox messages read; clears a due reminder), `t` opens the delegation tree, `z` snoozes off home across devices (`1h` default, max `7d` in `reminders.<human>`, cleared on wake or new item), `u` marks the latest message unread, `b` sets/resets a reminder, and `Enter` opens the thread.
- **Work & channels:** work groups threads by state and latest activity (`TURNS`, `SPEND`, age, live status), showing the selected thread's TL;DR (`S` refreshes) and delegation chain. The title keeps 30 columns at least: as the view narrows, the `NOW`, `SPEND`, `TURNS`, `OWNER` and `ANTS` columns give way in that order. Across the views, text cut to fit ends in `…`, and a line of keys too long for its card drops its last hints whole. Opening a channel shows a header of three panes: the channel with its notify level, description (cut to fit), owner and messenger; its members, each ant with its face and its state as the nav marks it and each human by name, the owner marked `★` and the messenger `✉`; and its latest activity, newest first: new threads and replies at their stored times, and reactions to opening posts, threads coming to be done, stuck or waiting on the human, and changes to the members, messenger, owner or description, each at the read that notices it (the last ones with no author). On a screen under 100 columns or 24 rows, one line sums the header up: channel, notify level, member count and latest activity. `M` opens an editor over the members pane (under a one-line header, over the top of the view), its keys taken until `Esc` closes it: a row per member, where `d` removes the member, then rows to add members (`a` or `@`: ants or humans, several at once, `@` completing those not in the channel), and to set the messenger (an ant in the colony), the owner (an ant) and the description (up to 1000 characters, counted as typed); `Enter` edits a row from what it holds; emptied, it clears it, as `d` does. Each change writes the channel's entry with the human's credentials as `ants channel set`, `add` and `remove` do, refused as they refuse it; the result or the error shows on the status line, and the header and the editor follow the entry once read back. Under the header, a row of tabs, `‹ all N · waiting on me N · working N · waiting on ant N · stuck N · idle N · done N · archived N ›` (those counting none left out on a screen too narrow for all), filters the channel's threads (`←`/`→` cycle them, and the tab chosen in each channel is kept in `chat-state.json` on the device): `all` lists every thread but the archived ones, each state tab those in that state, and `archived` the threads archived or auto-archived with no message since, as `ants channel read --archived` prints them. The view lists the top-level posts opening them newest first, each with its thread's state in its colour, attachments, reply counts, and reactions (`n` steps the channel's notify level through `all`, `humans` and `mentions` as `ants channel notify` does, shown in the header; in work, `u` marks the selected thread's latest message to the human unread across devices and `b` sets a reminder of the selected thread, and `f` forwards its TL;DR) and marks channel posts read across devices.
- **Teams:** opening a team shows a header with the team and the teams holding it (`within eng`), its description (three lines at most), lead (a dim `X (from team Y)` for one taken from above), owner and the count of teams beneath it, and, while it has no lead, nor any above it, the refusal its messages meet; under it, the members as a tree down through its member teams, as `ants team show` prints them: each ant with its state's mark, its face and its state in the colony, each lead marked `★ lead`, and each member team with its lead. `↑↓`, `PgUp`/`PgDn` and `Home`/`End` select a member, `Enter` opens it (an ant's view or a team's), and `a` writes `@TEAM ` in the command bar. `M` opens an editor over the members, its keys taken until `Esc` closes it: a row per direct member, where `d` removes one (the lead too, leaving the team without a lead of its own), then rows to add members (ants of the bus or teams on no team, `@` completing them), and to set the lead (another direct ant member; `d`, or an empty name, clears it), the owner (a human) and the description (up to 1000 characters). Each change writes the team directory with the human's credentials as `ants team add`, `remove` and `set` do, refused as they refuse it; the result or the refusal shows on the status line, and the view follows the directory once read back. `n` opens the form creating a team over the members, and the nav's `+ new team`, last of the teams, shows it alone (there `Esc` and the keys it has no use for go to the view): rows for the name (refused when a team, an ant or a human holds it), the lead (an ant of the bus on no team, `@` completing the ants; none leaves the team to take the lead of the team above it once put under one), the other members (ants or teams on no team), the owner (a human) and the description, `d` clearing a row, then a row whose `Enter` creates the team with the human's credentials as `ants team create` does, refused as it refuses it. `D` asks to delete the team and `y` confirms, as `ants team delete` does: it leaves the team holding it, and its members are then on no team. Each write tells observers on the human's status, as `ants team` does.
- **Thread view, attachments, trees & search:**
  - *Conversation & side panel:* renders messages, posts, and notes as terminal markdown (`❯` human, `●` ant; code blocks behind `▎` with `▎↳` continuation), interleaved with tool calls (`Name(args)` with status bullet and duration) and `ended without a reply` lines joined by `⎿` (`T` cycles `all` / `collapsed` (default summary + 3 latest running calls) / `none`, persisted in `chat-state.json`), trail steps (`◆ step N LABEL → ANT · STAGE · thread STEP_THREAD`, STAGE `started`, `waiting on a human` once the step's ant asked one with `ask_human`, `answered`, `failed` or `dropped`, live from `step` status events and loaded from `ants_trail_runs`; `Enter` or double-click opens the step thread, [trails.md](trails.md#the-run-thread)), `wake from <provider>` self-messages, dim daemon notices (yellow and stuck when human action is required: a notice that an ant's harness cannot serve holds the thread only until that ant answers on it, as its messages wait for the harness), nested delegations, and live reactions (`+` picker). With `inline_images = true` in `[cli]`, up to 12 visible PNG/JPEG/GIF/WebP attachments render via Kitty, iTerm2, Sixel, or half-blocks. From 140 columns (or toggled via `Ctrl-\`), a side panel shows state, owner, active ants, turns, spend, age, origin, held approvals, and touched files (one summary line when folded).
  - *Active waiting card:* at most one third of the view under the conversation shows the card keys currently answer (focused question, else oldest pending tool request, else latest unanswered question; question cards fold while a tool request waits), counting any others (`Ctrl-L` lists all, below); `Enter` opens full request details or focuses the question card, and `a`/`A`/`r`/`n` or `1`–`9` act once a message is selected.
  - *Keys* (letter keys act after `↑` selects a message; while writing, human replies steer a running prompt on the thread, channel replies included, and `/later TEXT` queues behind it without steering, showing `queued · N ahead`): `↑↓` select or line-scroll tall messages, `PgUp`/`PgDn` half-page scroll, `Home`/`End` and `Ctrl-Home`/`Ctrl-End` jump to ends (`↓ N newer · End shows them` when scrolled up), `i` return to writing, `v` view in `$PAGER`/editor, `y` copy to clipboard ([Terminal interaction](#terminal-interaction)), `Ctrl-F` case-insensitive find (`Enter`/`Shift-Enter` then `n`/`N` step matches, overriding reject-note `n`; `Esc` clears), `>` quoted reply (pre-fills `@<author> ` for ants; `Esc` on empty bar drops quote), `f` forward selected message or thread TL;DR ([Forwarding](#forwarding)), `u` mark unread from selection on and close, `b` set reminder, `p`/`m`/`e`/`d` toggle pin/mute/archive/done, `]`/`o` cycle and open attachments via system viewer (`open`, Windows default app, `wslview`, `xdg-open`), `x`/`Ctrl-X` cancel running prompts (`y` confirms in-flight tool calls), `W` withdraw a waiting human message or unanswered channel post (`E` withdraws and reloads text + attachments into an empty bar to edit), `t` open delegation tree (`ants_links`; `x` then `y` cancels subtree), and `/` open the palette (`Ctrl-F` outside threads opens `/search` with `from:`, `to:`, `channel:`, `type:`, `since:`, `until:`).
- **Ant view, credentials & held orders and decisions:** selecting an ant shows `ants ant show` beside its animated pixel-art avatar head (`[cli]` `theme` and `animate`), live thread progress and UTC-day spend in a box as high as the head (without one, as the `ants ant show` rows with a one-line whoami; at most half the view), whose about and now columns scroll separately (`\` switches the focused column, `[`/`]` scroll it a line, the bottom border counts the lines past it), tabs (`←`/`→`) for threads (those where it exchanged a message with a human or posted to a channel, not those where only other ants messaged it, as a reply there reaches another ant; `w` filters work the same way), waiting queue (`ants queue`), memories (`ants ant memories`), MCP servers (`ants ant mcp`, only for harnesses reporting them: protocols `claude`, `codex` and `copilot-sdk`, which the colony entry's `mcp` tells; `s`/`Enter` signs in to the selected server and shows the address to open, `y` copies it, `v` hands over the address a browser elsewhere came back to), and settings/admin orders (`Enter`/`n` edits `KEY = VALUE` via `ants ant set`, `r` restarts harnesses once `y` (after their prompts) or `!` (at once, cancelling them) confirms, `p` pauses or resumes the ant once `y` confirms, `C` pre-fills `/clone ANT `, `X` pre-fills `/retire ANT`, `a` pre-fills `@ANT`); `R` reads the memories, MCP servers and settings again as it reads everything else. On the account-key machine, `ants chat` polls pending `ants add --enroll` and `ants renew` requests every 15 s (`c` opens the credentials page to approve/sign with `a` or reject with `r`); on every machine, `o` opens what waits for the human's confirmation, oldest first: the assistant's admin orders the machines' daemons hold (gathered every 15 s) and its decisions on pending tool requests their ants hold (`a` confirms, `r` denies the selected one once `y` gives the answer, as `ants assistant confirm ACT [--deny]` does); home counts them, and a tool request's card names the decision (`pa chose allow-once for alice: o lists it`).
- **Direct messages:** selecting a person lists DM threads newest first, archived ones left out (what is typed is written in the command bar, which writes to the person on a new thread, sealed; with a thread selected, `n` focuses it), opening sealed messages and titles with the device key (`🔒`; `[sealed]` if pre-enrollment, `[forged]` on verification failure).

- **Waiting cards on a thread:** `Ctrl-L` lists every pending tool request and unanswered question message on the open thread, including older questions folded behind the visible card. The card's count, the footer, `?` help and the palette name the key. `↑↓`/`j`/`k`, `PgUp`/`PgDn` and `Home`/`End` select; `Enter` opens the selected request in the existing full details, or focuses the selected question's existing card and tabs, even while a tool request waits. `Esc` from request details returns to the list; `Esc`, `q` or `Ctrl-L` closes the list. Draft text stays in the bar; letters in the list select or do nothing rather than being sent or answering a hidden card. Outside the list, `Enter` on an empty bar still opens the oldest tool request, else focuses the latest waiting question.

### Terminal interaction

`ants chat` enables mouse reporting by default (`[cli] mouse = false` disables it). The wheel scrolls the
conversation, list or overlay under the pointer one line at a time. Click a row, navigation entry, state tab,
question option or completion to select it; click again to open or apply it. Over the box of a run `/trail run`
asks to start, the mouse does nothing: keys alone answer it. Hold Shift for native terminal text selection, or Option
in iTerm2. Mouse reporting stops on exit, panic and editor or pager handover.

The terminal reports focus while chat runs. A new item on home rings the bell once while unfocused.
`[cli] notify = "terminal"` uses terminal notifications (OSC 99 on kitty, OSC 777 on rxvt, OSC 9 otherwise);
`notify = "off"` disables these announcements. The tab title shows `ants (N)`, with the number of home items,
and the previous title is restored on leaving. Device presence and push-sink suppression stay unchanged.

With a message selected, `y` copies through the first available local `pbcopy`, `wl-copy`, `xclip` or `clip.exe`.
Over SSH, or without a clipboard executable, it sends OSC 52 instead. The notice identifies the transport;
command failures are errors, and OSC 52 reports an unacknowledged request rather than confirmed clipboard contents.
A message containing code blocks opens a chooser: the whole message first, followed by each code block.
Links and bare HTTP(S) URLs become OSC 8 hyperlinks on known supporting terminals, including iTerm2, kitty,
WezTerm, foot, Ghostty, VTE and Windows Terminal; terminal-specific link-opening modifiers still apply.

On Unix, `Ctrl-Z` restores the terminal and suspends chat; `fg` resumes and redraws it. Mouse and focus reporting
are disabled while an external editor, pager or shell owns the terminal.

### `ants chat` command bar

An empty command bar says what `Enter` does with plain text in the active view. A message (not a post) whose text @mentions two or more ants or humans is refused with nothing sent, as `ants ask` refuses it: addressing several takes a post in a channel ([architecture.md](architecture.md#one-recipient)).

- **Palette (`Ctrl-K` or `/` on an empty bar):** lists slash commands, active view keys, and places (channels, ants, people, and work threads, unread/waiting first), narrowed without sigils (`/ops` matches `#ops`) and dimming unavailable actions with why (`/archive (no thread open or selected)`). `↑↓` select, `Enter` runs/navigates (or completes an argument-taking command), `Tab` completes, `Esc` closes, and `Backspace` on `/` leaves an empty bar. Unknown or malformed slash commands open the matching palette beside their error.
- **Line editing, newlines & pastes:** with text in the bar, `Ctrl-K` or `/` focuses it (`Esc` unfocuses keeping text; `Enter` sends). `Ctrl-J`, `\` + `Enter`, and `Shift-Enter`/`Alt-Enter` (via kitty keyboard protocol disambiguation) insert newlines; `Ctrl-G` or `Ctrl-X Ctrl-E` opens `$VISUAL`/`$EDITOR`; `Tab` completes `@` users and teams (each with its lead), `#` channels, and `/attach` paths. Readline keys (`Ctrl-A`/`E`, `Home`/`End`, `Ctrl-K`/`U`, `Ctrl-W`, `Alt-Backspace`/`D`, `Ctrl-Y` yank, `Alt-B`/`F`, word arrows, `Up`/`Down`) work across the bar and all single-line TUI inputs. Pastes keep newlines; pastes > 800 chars or 3 lines collapse to `[Pasted text #1 +N lines]` tokens, pastes > 64 KiB attach as `paste-1.txt`, and dropped image paths attach automatically.

- `@ant TEXT` starts a new thread with `ant` (`@team TEXT` with the team's lead, carrying the team as `ants ask @TEAM` does, refused while neither the team nor any above it has a lead; the thread view's title then ends in `via team TEAM`) (on an open channel thread or a channel's feed, posts there mentioning `ant`); `#channel TEXT` posts to `channel`; plain text replies on the open thread (or posts a new thread on the channel on view, DMs the selected person, else sends to the human's assistant or `system-messenger`); `//TEXT` sends literal leading `/`.
- Slash commands act on the open or selected thread: `/approve [ID] [--always]`, `/reject [ID]`, `/grant [TEXT]`, `/cancel`, `/later TEXT` (reply on the open thread, waiting behind the prompt running there as `ants ask --queue` does), `/answer PICK...` (the questions of the card the keys answer, a pick for each as `ants answer` takes them), `/done`, `/undone`, `/pin`, `/unpin`, `/mute [DURATION]`, `/unmute`, `/notify all|humans|mentions` (the notify level of the channel on view, or of the open channel thread's channel), `/notify snooze DURATION | resume | status` (below), `/snooze [DURATION]`, `/unsnooze`, `/remind DURATION|TIME [NOTE]`, `/unremind`, `/reminders`, `/schedules` (the config file's schedules as `ants schedule list` prints them, in the pager), `/archive`, `/unarchive`, `/title TEXT`, `/notes TEXT` (post to the thread's notes as `ants notes THREAD TEXT` does, with the files `/attach` staged: in the clear, even on a thread between two humans, waking nobody and renewing their turn budget), `/react NAME`, `/goto THREAD|#channel|@user`, `/search QUERY`, `/tree`, `/forward @ant [TEXT]`, `/save [PATH]`, `/tldr`, `/digest [SINCE]`, `/attach PATH`, `/detach`, `/add NAME --on MACHINE [FLAGS]` and `/clone ANT NEW [FLAGS]` (the admin orders `ants ant add` and `ants ant clone` send, taking their flags, `--wait` too, a quoted run of words one value and a leading `@` dropped from the names before the first flag; the bar's status line tells the outcome as they print it, or the error of a flag refused), `/retire ANT`, `/channel create NAME [--member USER,...] [--messenger ANT] [--owner ANT] | set NAME CHANGES | add NAME USER... | remove NAME USER... | delete NAME` (`ants channel create`, `set`, `add`, `remove` and `delete` with their words and flags, `--description` too, CHANGES being those of `ants channel set`, read as `/add` reads them and run with the same code: the status line tells what they print and warn of, or why they refuse, and the nav reads the channels again, so a channel created shows there; `@` completes every ant and human, after a comma of `--member` too, and `#` the channels), `/assistant enable [--name NAME] [--harness HARNESS] [--model MODEL] [--on MACHINE] | show [HUMAN] | disable [--retire] [--name NAME] | set ANT | clear | allow [RULE...] | allow --remove RULE... | allow --clear` (`ants assistant enable`, `show`, `disable`, `set`, `clear` and `allow` with their words and flags, the other flags of `enable` and `disable` too, read as `/add` reads them and run with the same code: the status line tells what they print and warn of, the pager all of it past two lines, or why they refuse; `/assistant disable` without `--retire` first asks in the footer: `y` withdraws the assistant and retires the dedicated one `enable` created, as `--retire` does, `n` withdraws it alone, any other key keeps it; `@` completes every ant and human), `/dead replay [SEQ] | drop [SEQ]` (below), `/trail list | show NAME|RUN | tips NAME [--key KEY] [--all] | tips NAME --retire ID [--writer ANT] | runs | run NAME [@ANT] [--steps N] [--at-once N] [--turns N] [--wall DUR] [--thread THREAD] [ARGS] | stop RUN | resume RUN [--steps N] [--at-once N] [--turns N] [--wall DUR]` (below), and `/quit`.
- **Dead letters (`/dead`):** `/dead replay` sends the message of a dead letter to its ant again, as it was, and `/dead drop` removes the dead letter unreplayed, as `ants dead replay` and `ants dead drop` do with the same code: the dead letter at `SEQ` (as `ants dead list` numbers it), else the one selected in the thread view (its `gave up` line, or the daemon's notice of giving up on the message), else the latest of the thread open or selected, such as home's stuck item. A drop first names the dead letter in the footer: `y` drops it; any other key keeps it. The status line tells the outcome. A dead letter replayed or dropped, here or before `ants chat` read the thread, and the notice of it leave its thread stuck no more on home and in work.
- **Trails (`/trail`):** `/trail list`, `/trail show NAME|RUN`, `/trail tips NAME [--key KEY] [--all]` and `/trail runs` show in the pager what `ants trail list`, `ants trail show`, `ants trail tips` and `ants trail runs` print: the saved trails, with who saved each, a saved trail's meta and script or a run's record, pending calls and journal (a name no saved trail has is taken for a unique start of a run's id), a trail's tips (the status line counting the live and retired ones), and the runs, followed by the top 3 live tips of each of the trails of the latest runs that have any (id, tip key, votes and the start of the text). `/trail tips NAME --retire ID [--writer ANT]` retires a tip as `ants trail tips --retire` does, the status line saying so. `/trail run NAME [@ANT] [--steps N] [--at-once N] [--turns N] [--wall DUR] [--thread THREAD] [ARGS]` starts a run of the saved trail `NAME` (the colony's before this machine's `~/.ants/trails/NAME.py`, sent inline) with `ARGS`, after the conductor and options in any order, as its JSON `args` (at most 64 KiB), on the conductor `@ANT`, else the human's assistant, else the messenger, under the limits `ants trail run`'s flags of the same names set (the same defaults and maxima, refused alike), reporting on `--thread`, else a new thread: an id or a unique start of one among the threads read, as `/goto` takes it, `last` for the most recently active of them, or `here` for the thread slash commands act on. It first shows over the view what `ants trail run` prints before asking (the trail, its conductor and thread, and the limits chosen; on a screen too short for it all, the description is cut to the rows left, a last row saying how many more it has, so the conductor, thread and limits stay shown), then `y` starts the run and shows its thread, `?` the help, and any other key leaves it unstarted. `/trail stop RUN` and `/trail resume RUN [--steps N] [--at-once N] [--turns N] [--wall DUR]` (a run's id or a unique start of one) stop and resume a run as `ants trail stop` and `ants trail resume` do, a stop that leaves steps waiting in other ants' queues counting them on the status line and showing in the pager what `ants trail stop` prints, each step with its `ants withdraw ANT MESSAGE`, a resume's limit options replacing those of the run's limits they name as `ants trail resume`'s flags do (the same maxima, refused alike, read as `/trail run` reads them). Each sends the requests of `ants trail` with the same code; `--json` and `--follow` have no counterpart, the run's thread listing its steps instead.
- **Reminders (`/remind`, `b`):** `/remind 2h check the deploy`, `/remind 09:30` (the next such time on the local clock), `/remind 2025-07-01T09:00 NOTE` (local) or an RFC 3339 time reminds of the selected message in the thread view, else of the thread; `b` asks for the same in the command bar. One reminder per thread is stored per human at `reminders.<human>` in `ants_threads` (CAS, setting another replaces it). Once due, it shows as a `reminder` home item on all the human's devices, and `ants webhook serve` pushes it once ([webhooks.md](webhooks.md#quiet-hours-snooze-and-muted-threads)); `d` on the item or `/unremind` clears it. `/reminders`, from any view, shows every reminder of the human, those not due yet too, in the pager as `ants remind list` prints them (soonest due first: when, `due` and `pushed`, the thread and message, the note and the thread's title), the status line counting them and those due; `/goto THREAD` shows a thread listed. Outside `ants chat`, `ants remind set|list|clear` does the same: `ants remind set 0193 2h check the deploy` reminds of message `0193…` (else thread `0193…`), and `ants remind list --json` prints one JSON reminder per line (with `thread`, `is_due` and the thread's `title`).
- **Push notifications (`/notify`):** from any view, `/notify snooze DURATION` (`1s`–`365d`) holds back the push notifications of `ants webhook serve` on every device of the human (but those `bypass` lets through), `/notify resume` ends the snooze, and `/notify status` shows what holds them back: the snooze on the status line, with the muted threads (`/mute`) and the channels' notify levels other than the default (`/notify all|humans|mentions`) counted there and listed in the pager. Each runs the code of `ants notify snooze|resume|status` on the same entry ([webhooks.md](webhooks.md#quiet-hours-snooze-and-muted-threads)); quiet hours stay in the webhook config, and `--json` has no counterpart.
- **Title and drafts:** the bar's title says what `Enter` does with the text as it stands, the routing above applied to it: `reply to dev-b on "deploy the site"`, `new thread in #ops`, `post in #ops on "TITLE"`, `to bob on a new thread, sealed` (a human other than oneself), `to team backend (lead dev-a) on a new thread`, `to the assistant or the messenger on a new thread`, `run /done`; an `@user` or `#channel` typed first changes it as typed, and `Enter` sends where the title said. The bar's text is the draft of the conversation it was typed in (a thread, a channel's feed, a person's DMs, or none): another view shows its own draft, back in the conversation the draft is in the bar again, and the nav, the work lists, home and a channel's feed mark the conversations holding a draft with `✎`. A send that fails comes back as the draft of the conversation it was typed in.
- **History:** in the focused bar, `Ctrl-P` and `Ctrl-N` recall the texts sent from the bar, latest first (`Ctrl-N` past the latest puts back the text typed), and `Ctrl-R` searches them, latest first and whatever the case: typing narrows the search, `Ctrl-R` again goes to an earlier match, `Enter` takes the text found into the bar without sending it, `Esc` or `Ctrl-G` puts back the text before, and any other key takes the text found and acts. `Esc` twice within a second on a bar holding text empties it into the history. The latest 200 texts and the drafts of the conversations are kept on the device in `chat-bar.json` beside `chat-state.json`, readable by its owner only, and come back in the next `ants chat`. A text or draft addressed to another human (in a DM, on a thread outside channels with another human on it or not read yet, or mentioning one with `@`), which goes sealed, and a slash command acting on such a thread (the one open or selected, any thread when not known, as for a draft of home kept while away) are kept for the run only and never written to disk.

### `ants dash`

`ants dash [--since DUR]` (human creds + TTY, default `24h`) displays active threads (`▶` while busy, `done` when marked), selected thread live progress and history, 10 s colony refresh, (live progress comes from best-effort status updates: each colony read takes an ant's progress off the threads last heard from before its heartbeat when its entry is gone, its daemon restarted since, or it had fewer messages in hand than such threads, those heard from longest ago first, so an update lost, or missed while disconnected, leaves no thread busy for good; `ants chat`'s `working` state follows the same) and live pending tool requests (`Enter` inspects, naming what `allow_always` allows as the harness does; there `a`/`A`/`r` decide `allow_once`/`allow_always`/`reject` at once, a note with the rejection being `ants chat`'s `n` or `ants tools reject --note`; `Tab` switches panes, `R` refreshes, `q`/`Ctrl-C` quits). Records approval presence while open.

### Reactions

`ants react MESSAGE REACTION [--remove]` and MCP `react` store `<reactor>.<message_id>.<reaction>` in `ants_reactions` (30 d TTL; requires hub reachability). Humans write/delete only their own keys and read all reactions across `ants inbox`, `ants thread show`, `ants watch`, `ants chat`, and `-f` followers; reactions never end a wait or mark messages read. Humans may pass a unique message-ID prefix (7 d lookup); ant credentials require full UUIDs and call `ants signer` (or `ants webhook serve` for `list_reactions`, or in-process on unauthenticated servers) over `_INBOX.<ant>.reactions`, scoped strictly to messages the ant reads ([auth.md](auth.md#wire-acls-and-verification-invariants)).
