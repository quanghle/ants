# CLI and terminal UIs

The `ants` binary provides scripting commands, daemon and service subcommands, and interactive terminal interfaces (`ants chat` and `ants dash`).

## Commands

| Command | Description |
|---|---|
| `ants ask [--thread THREAD] [--reply-to MESSAGE] [--plaintext] [--wait \| -f] [--timeout DUR] [--attach PATH]... [@ant] TEXT \| --file PATH \| --edit` | Send to `@ant`, else to the human's assistant while its [grant](auth.md#assistant-grant) stands, else to `messenger`; prints `thread <id>`, `message <id>`, `to <ant>` without `@ant` (`to pa (assistant of alice)`), and `attachment <handle>` per `--attach` file. From a human to `@HUMAN`, seals text and attached files for both humans' devices, or refuses without sendable keys unless `--plaintext` ([auth.md](auth.md#sealed-messages-between-humans)). Human messages automatically interrupt a running prompt on the same thread and prompt the same session next, ahead of the queue ([config.md](config.md#prompt-limits-and-spending-caps)). Warns on stderr if `@ant` is missing from `ants_colony`, `stale`, `signed-out`, `failing`, or provider-limited with no fallback answering. `--reply-to` (a message id, or a unique prefix with human creds, as `ants react` takes; human creds only) replies to that message: on its thread (`--thread` must name the same one), to its author without `@ant` unless the CLI's human wrote it, and quoting its author and a 160-character excerpt (see [Quoted replies](#quoted-replies)). |
| `ants inbox [--peek] [--thread THREAD] [--limit N] [-f] [--json]` | Print unread replies (with message IDs and reactions; an ant's face before its name) and mark read across all devices (`--peek` keeps unread; `-f` streams replies, reactions added/removed to shown messages (human creds; `--json`: `{message, by, reaction, removed}`), `MAX_DELIVERIES` advisories, and, without `--thread`/`--json`, tool requests; records presence without `--thread`). Attachments show as `📎 name (size) handle` lines; `--json` gives each reference with `handle`. |
| `ants colony [--json]` | List ants after each one-line avatar face such as `(ovo)` in its colour (`live`/`stale`, `idle`/`working`/`paused`/`signed-out`/`failing`/`rate-limited`/`out-of-quota`/`fallback`), daemon/perms versions, harness and `AGENT` (`name@version`), capabilities, `escalate_to`, and workdirs, plus notes on moved ants (`ants ant export --move`), version/settings drift, recovery, memory pressure, and duplicate face/colour warnings. `--json` adds `born`, `avatar`, `color`, and `prompts` from `ants_identities` (`null` without one). |
| `ants ant show ANT [--json] [--config FILE]` | Show one ant at a glance, matching the ant view of `ants chat`: colony entry (machine, harness, model, workdir, capabilities, version), active holds, waiting queue, spend that UTC day, latest 10 threads, machine `config.toml` settings (secrets hidden; read afresh via `read_settings` admin order with admin creds, else as last read), shared settings (marked `NOT VERIFIED` with the reason when verification fails), and latest 10 admin orders. |
| `ants ant avatar ANT [--seed S \| --reset] [--color C \| --auto-color]` | Print the ant's pixel-art avatar head (coloured half-blocks on a terminal, else ASCII), face, parts, colour, birth, and growth stage (`callow` < 10 prompts, `worker` ≥ 10, `veteran` with scar ≥ 100, `elder` with crown ≥ 1000). `--seed`/`--reset` and `--color` (12 hue names)/`--auto-color` update `ants_identities` via compare-and-set. Human creds. |
| `ants ant set ANT KEY=VALUE... [--no-wait]` | Change an ant's settings in `config.toml` on its machine, or in its [shared settings](config.md#shared-settings) (`whoami`, `memory`, `capabilities`, `model`, `reasoning_effort`, `context`, `fallback`, `allow`, `escalate_to`): reads current values first and sends a `set` admin order expecting those values so concurrent edits fail naming the changed field. `KEY` targets the ant's `[[ant]]` table or shared `harnesses.NAME.*`; `VALUE` is TOML (bare words read as strings, empty removes the field). Waits up to 10 s unless `--no-wait` ([auth.md](auth.md#admin-orders)). Admin device creds. |
| `ants ant pause ANT [--machine M] [--wait DUR]` | Pause an ant via admin order (`paused = true`): stops pulling new prompts while running prompts finish and harnesses stay live ([config.md](config.md#pausing-an-ant)). Waits `--wait` (default `10s`). Admin creds. |
| `ants ant resume ANT [--machine M] [--wait DUR]` | Resume a paused ant via admin order, removing `paused` so queued messages run in turn. Admin creds. |
| `ants ant memories ANT [--json] [--machine M]` | Read an ant's memories via `read_memories` admin order while its daemon is online: core memories (`whoami`, `memory`, `tasks`), read-only size-capped harness `memory_files` ([config.md](config.md#memory-files)), and `BD_DB` memories. Admin device creds. |
| `ants ant export ANT [-o FILE] [--move] [--config FILE]` | Export an ant to a plain JSON file (default `./ANT.ant`, mode `0600`, never overwritten): identity record, verified shared settings (or config settings with a warning), and home memory files packed between prompts ([config.md](config.md#exporting-and-importing-an-ant)). `--move` marks the ant moved so daemons drain and stop serving it. Human creds. |

Human creds. |
| `ants ant unseal ANT` | Clear the `moved` mark set by `ants ant export --move` so daemons serve the ant again. Human creds. |
| `ants ant orders ANT [--json]` | List admin orders to `ANT` across machines, oldest first (`pending`, `held`, `applied`, or `refused` with reason; `<human> via <assistant>` for assistant orders) ([auth.md](auth.md#admin-orders)). Human creds. |
| `ants ant restart ANT [--now] [--machine M] [--json]` | Order the serving daemon to restart `ANT`'s harnesses: idle ones stop immediately, working ones after their prompt or cancelled immediately with `--now`; next prompts resume sessions in fresh processes ([auth.md](auth.md#admin-orders)). Admin device creds. |
| `ants ant add NAME --on MACHINE [settings] [--wait DURATION]` | Add an ant remotely by [admin order](auth.md#adding-and-retiring-an-ant-by-order): the machine's daemon generates the key, `ants signer` signs it, credentials and `[[ant]]` are written, and the ant starts. Admin creds; `ants signer` running. |
| `ants ant retire ANT [--machine M] [--wait DURATION]` | Retire any config-listed ant by admin order: table removed, ant drained, key revoked by `ants signer`, credentials deleted, home kept, and leaf uplink shrunk (`X` in `ants chat` ant view). Admin creds; `ants signer` running. |
| `ants ant clone SRC NEW [settings] [--machine M] [--wait DURATION]` | Clone `SRC` to `NEW` on `SRC`'s machine by [admin order](auth.md#cloning-an-ant-by-order): pauses `SRC`, copies home, thread histories, worktrees (`ants/NEW/<thread>` with uncommitted changes), and `[[ant]]` settings, forks or seeds sessions, signs `NEW`'s key via `ants signer`, and resumes `SRC`. Admin creds; `ants signer` running. |
| `ants machines [ANT] [--json]` | List machines recorded in `ants_machines` (machine, host name, version, timestamp, ants) plus the account-key holder `_account`; with `ANT`, list machines serving it, latest first. Human creds. |
| `ants spend [ANT] [--thread THREAD \| --days N] [--json] [--config FILE]` | Report token and cost spend over UTC days (default 7, max 366) or on a thread against local config caps ([config.md](config.md#spend-report)). |

### Thread and message identifiers

`THREAD` in `ask`, `inbox`, `post`, `notes`, `thread show`, `thread title`, `thread pin`/`unpin`/`archive`/`unarchive`, `thread done`/`undone`, `thread mute`/`unmute`, `cancel`, `watch`, `spend --thread`, and `channel read --thread` accepts a hyphenated UUID (used without lookup), a unique prefix (or non-UUID thread ID), or `last` (latest thread the human sent or received on). Prefix lookup (human creds only) checks the human's own threads from the last 7 d first, then all threads in the last 7 d (bounded to `[-5m, +10m]` around the timestamp encoded in a UUIDv7 prefix); exact matches win, and ambiguous or missing prefixes list candidates (id, time, title where readable, route, and first line of the latest message).

### Quoted replies

A quoted reply (`ants ask --reply-to`, `ants post --reply-to`, or `>` in the `ants chat` thread view) names the message it replies to in `in_reply_to` and carries `quote`: that message's author and its text with whitespace collapsed, cut at 160 characters with `…`. The daemon starts the prompt for it with `[ants] In reply to <author>: "<excerpt>"`, since the ant may not hold the message (another ant wrote it, or it is from an earlier session). `ants thread show` and the thread view show `↪ replying to <author>: <excerpt>` above its text. Between humans, the quote is sealed with the text. A sealed message's excerpt never goes in the clear: a reply quoting one that is not sealed itself (to an ant, a channel post, or `--plaintext`) carries only the author, shown as `↪ replying to <author>` and prompted as `[ants] In reply to a sealed message from <author>.`. The CLI reads the message back with the human's credentials to quote it (a message kept over the last 7 days), so a sealed message that does not open on the device cannot be quoted.

## Identity, setup, completions and doctor

- **Connection & identity:** every command accepts `--nats`, `--creds`, and `--js-domain`, falling back to `[cli]` then top-level keys in `ANTS_CONFIG` (`~/.ants/config.toml`), except `ants daemon` and `ants add` (which read top-level config directly). NATS URLs containing credentials or tokens are rejected. Connecting with human credentials ensures `ants_humans` contains `<name>` (`human` needs no entry) and runs an `ants init` pass creating missing objects. Ant credentials skip `ants_humans`, warn, refuse `ants inbox`, and leave `--wait`/`-f` replies unread.
- **`ants setup`:** without `--harness` and an existing config file, chooses the harness of a new config by looking up each built-in's command on `PATH` (no handshake): a single installed harness is picked and reported, multiple are offered in a numbered terminal prompt (failing without a TTY), and none installed fails with install and sign-in commands ([config.md](config.md#choosing-a-harness-in-ants-setup)). Setup then idempotently writes `~/.config/ants/nats.conf` (JetStream in `~/.ants/jetstream`, skipped for non-loopback `--nats` or existing `leaf.conf`), installs/starts `ants.nats` / `ants-nats`, runs `ants init`, creates/appends `~/.ants/config.toml`, runs `ants harness check`, issues host credentials when ants have credentials and team keys are local ([auth.md](auth.md#machine-host-credentials)), installs/starts/reloads `ants.daemon` / `ants-daemon`, installs shell completions, and runs `ants doctor --no-harness` (`--dry-run` previews without changes). `--managed-nats` (loopback `--nats` only) installs no NATS service: a new config file gets a [`[nats_server]`](config.md#managed-nats-server) table naming `leaf.conf` when present, else `nats.conf` (with `command` from `--nats-server`), the daemon service is installed or restarted, and `ants init` runs once the daemon's server listens (`--no-services` prints `ants daemon --config FILE` instead). It fails while an `ants.nats` / `ants-nats` unit is installed for that configuration, printing the commands that remove it, or, for a new config file, while a server listens on the address already; an existing config file is not edited, and without the table its step fails naming the line to add and the daemon restart to run.
- **Shell completions:** `ants completions --install` writes to `~/.local/share/bash-completion/completions/ants`, `~/.local/share/zsh/site-functions/_ants` (add to `fpath` before `compinit`), or `~/.config/fish/completions/ants.fish` (`XDG_DATA_HOME`/`XDG_CONFIG_HOME` honoured). Dynamic lookups (`ANTS_COMPLETE`, 2 s timeout, silent on error, skipped for OS-keystore seeds) complete `@ant` / ant names, channels, `last` + recent 7 d threads (with thread `title`, else latest line), the latest 50 messages to or from the CLI human over 7 d matching the typed prefix and suggested reactions on `ants react`, pending tool requests, and dead-letter sequences.
- **`ants doctor`:** read-only end-to-end check (`ok`, `warn`, `fail`, `skip`, with `fix` commands; 5 s per request, 10 s per network check, 60 s per harness handshake). Checks `config`, CLI `credentials` + OS `credentials key` + device `credentials xkey`, `server` (failing below `nats-server` 2.15) + `jetstream`, `hub` objects, `consumers` (`≥ 80%` of `max_consumers`), team `versions` + cross-machine `harness versions` + `shared settings` drift + `avatars` + `moved ants`, JetStream `storage`, `host credentials` and `machine name`, per-ant `credentials` / `harness` / shared git `workdir` / `reactions` / `tool permissions`, `hub resolver` (`full` resolver) + `team keys backup`, `leaf` / `leaf uplink` / `leaf system uplink` / `leaf node` / `outbox`, installed `daemon` / `leaf node` / `hub` / `webhook` services (the configuration `[nats_server]` names checked as run by the daemon service, failing when an `ants.nats` / `ants-nats` unit runs it too: [operations.md](operations.md#managed-nats-server)), `webhooks.toml` secrets (`0600`) / `exec` commands / `public_url` `/_approval` probe, and installed `devtunnel` / `bridge` services, tokens, and reachability.

## Composing and waiting

- **Input:** `ants ask` and `ants post` take trailing words joined by spaces, `--file PATH` (`--file -` reads stdin; preserves internal formatting, strips BOM and trailing newlines), or `--edit` (`$VISUAL` -> `$EDITOR` -> `vi`/`notepad` on a `0600` temp file; empty/blank messages abort).
- **Attachments:** `--attach PATH` (repeatable; `ants ask`, `ants post`, and `ants notes` with `TEXT`) attaches up to 8 regular files of at most 8 MiB each, named by base name and typed by extension (`application/octet-stream` otherwise). Files are stored in `ants_files` before sending; any failure sends nothing. Each attachment gets a handle `<sender>.<inbox|notes|chan>.<target>.<id>` accepted by `ants attachment get`.
- **Sealed messages:** messages between two humans are sealed end to end for their devices' keys in `ants_devices` and any device-enrolled assistant (`ants assistant seal on`), unless `--plaintext` is set. Readers print opened text, looking up newly enrolled sending devices on demand, else `[sealed]` (no key for this device) or `[forged]` (decryption/sender failure); `--grep` matches opened text only, and `ants watch` and dead letters show `[sealed, N bytes]` ([auth.md](auth.md#sealed-messages-between-humans)).
- **Waiting:** `--wait` prints the first reply and exits `0` (`--timeout` exits `1` on timeout; Ctrl-C exits `130`); `-f`/`--follow` streams replies until `--timeout` or Ctrl-C (`0`), marking printed replies read, plus live reaction changes on the sent message and printed replies (human creds). On a terminal with human credentials, stderr displays an in-place status line (`not served`, `queued behind N`, `working`, `thinking`, `writing`, `running <tool>`, `waiting for approval` with `ants tools approve <ant>/<id>`, `harness signed out`).

## Threads, search, titles, done states and marks

`ants thread list`, `show`, and `search` read `ANTS` with human credentials via batched direct gets (`$JS.API.DIRECT.GET.ANTS`, 256 messages/request), consuming and marking read nothing. Entry kinds: `message`, `escalation`, `mention`, `post`, `note`, `approval`, `decision`, `dead` (subject mismatches marked `(forged)`).

- **Search (`ants thread search`):** combines `--from`, `--to`, `--channel`, `--type`, `--grep` (case-insensitive), `--since` (inclusive, default 24 h before `--until`), `--until` (exclusive, default now; accepts durations, RFC 3339, or UTC `YYYY-MM-DD[ HH:MM]`), and `--limit` (default 50). `--from`, `--to`, and `--type` prune scanned subjects server-side.
- **Titles (`ants thread title`):** 1–120 trimmed single-line chars stored at `title.<thread>` in `ants_threads`, shared across humans and shown in `thread list`, `thread show`, `ants chat`, and tab completion. An ant's suggested title (`suggest_thread_title`, carried on its reply) is stored by the next human `ants thread list` or `thread show` via CAS only if `title.<thread>` has no entry and no delete marker (`(suggested by <ant>)`). On threads carrying sealed messages between two humans, `ants thread title` seals the title for both humans' devices (`[sealed]` elsewhere) and ignores ant suggestions ([auth.md](auth.md#sealed-messages-between-humans)).
- **Done (`ants thread done|undone`):** shared state at `done.<thread>` in `ants_threads` (`ThreadDone {thread_id, by, at, after}`); changes no ant's work, reply, or notification. Any message, channel post, or note stored above `after` reopens the thread at read time without a write (tool requests, decisions, and dead letters do not). `ants thread undone` writes a delete marker with a 1 s per-message TTL.
- **Pins & archives (`ants thread pin|unpin|archive|unarchive`):** per-human CAS state at `marks.<human>` in `ants_threads` (mutually exclusive). Pinned threads sort last and survive `--limit`; archived threads hide from `ants thread list` and `ants dash` until new messages arrive (`archived+new`).
- **Auto-archive (`auto_archive` in `[cli]`):** off by default; with e.g. `auto_archive = "14d"`, an unpinned, unarchived thread with no entry stored for that span counts at read time as `auto-archived` (`auto_archived` in `--json`) and hides from `ants thread list` and `ants dash` until a new entry arrives. `ants thread unarchive` stores a `kept` timestamp in `marks.<human>` for one more `auto_archive` idle period.
- **TL;DRs and digests (`ants thread tldr`, `ants digest`):** requested from `[cli]` `summary_ant` on dedicated summary threads hidden from thread lists, the inbox, and push notifications; see [config.md](config.md#catch-up-summaries).
- **Pruning:** `ants thread list` prunes marks, titles, TL;DRs, and done states of threads with no message remaining in `ANTS` (30 d retention + 30 d outbox grace), using CAS and revision-conditioned deletes with 1 s TTL delete markers.

## Terminal UIs and reactions

### `ants chat`

`ants chat [--since DUR] [--compact]` (also bare `ants` on a TTY; human creds, default `--since 7d`) opens the full-screen terminal chat UI. Without a TTY it exits naming the scripting commands; with no server reachable within 5 s it points to `ants setup` and `ants login`. Updates arrive live from `ANTS`, status events, and `ants_colony`, recording inbox and approval presence while open. `Tab` switches between navigation and the active view, `Esc` goes back, `R` refreshes, `?` lists shortcuts, and `q`/`Ctrl-C` quits.

- **Navigation & header:** the header shows the human, server, and connection state. The sidebar lists **home** (count of items waiting on the human), **work** (all threads plus counts by state: `waiting on me`, `working`, `waiting on ant`, `stuck`, `idle`, `done`), **channels** (bold unread counts and `@N` mentions), **ants** (`●` live, `◐` busy, `◌` limited/fallback, `‖` paused, `✕` signed out/failing, `○` stale, with each ant's coloured face unless `NO_COLOR` is set), and **people** (`●` online via `ants_presence`, `○` away, `·` unknown, with unread DM counts).
- **Home triage & `--compact`:** home's summary line counts changes since the previous session on the device (`chat-state.json` beside `config.toml`, else 24 h) and UTC-day spend; `s` opens/refreshes a digest overlay (`j`/`k` scroll). Below it, home orders items waiting on the human, one row per thread under its most pressing reason with badges for the others (e.g. `question · stuck · 2 mentions`; keys act on the top reason), most pressing first and oldest first within each kind: pending tool requests, unanswered `ask_human` questions, stuck threads, unread human DMs, unread mentions, and finished threads whose answer is unread (read on any device, a finished thread leaves home and stays in work). Keys act inline: `a`/`A`/`r` then `y` decide tool cards (`allow_once`/`allow_always`/`reject`; `Enter` opens full details; settled cards remain 2 min unless decided on this device), an ant's pending requests on one thread grouping into one card with their count and the oldest, which the keys answer, `Enter` listing them one by one (and on the group's head collapsing them), `1`–`9` or `r` (`/answer`) answer question cards, `g` grants fresh turns (`Carry on`), `r`/`f` reply or follow up, `x` cancels a running prompt, `d` marks done (and marks inbox messages on the thread read), `t` opens the delegation tree, `z` snoozes the thread off home across devices (`1h` default, max `7d`, `snoozed.<human>` in `ants_threads`, cleared on wake or new home item), and `Enter` opens the thread. `--compact` renders a two-line status + top-item pane with the same item keys (`Enter` expands to full screen).
- **Work & channels:** work groups threads by state and latest activity (`TURNS`, `SPEND`, age, live status), showing the selected thread's TL;DR (`S` refreshes) and delegation chain. Opening a channel lists top-level posts newest first with attachments, reply counts, and reactions (`w` filters work to that channel) and marks channel posts read across devices.
- **Thread view, attachments, trees & search:** renders messages, posts, and notes as terminal markdown alongside interleaved tool calls (from stored `Timeline` records and live status), dim `ended without a reply` lines for turns that sent no reply, nested ant-to-ant delegations, question/tool cards, and live reactions (`+` opens the reaction picker). With `inline_images = true` in `[cli]`, up to 12 visible PNG/JPEG/GIF/WebP attachments render via Kitty, iTerm2, or Sixel graphics (else half-blocks). From 96 columns, a side panel shows state, owner, active ants, turns, spend, age, origin, held approvals, and touched files. Keys: `↑↓` select message, `y` copy (OSC 52), `i` reply (human replies automatically interrupt a running prompt on the same thread, including channel replies delivered to the ant), `>` reply to the selected message (else the latest), quoting it: the command bar's title shows the quote and the bar is pre-filled with `@<author> ` when an ant wrote it, so the reply wakes that ant (edit or remove the mention before sending; `Esc` on an empty bar drops the quote, and a failed send brings it back with the text); a quoted reply shows a dim `↪ replying to <author>: <excerpt>` line above its text, `p`/`m`/`e`/`d` toggle pin, mute (as `ants thread mute` without `--for`), archive, or done, `]`/`o` cycle and open attachments in a private temp directory via system viewer (`open`, the default app of the file type on Windows, `wslview`, `xdg-open`), `x`/`Ctrl-X` cancels running prompts (confirming with `y` if a tool call is in flight), `t` opens the cross-thread delegation tree (`ants_links`; `x` then `y` cancels a selected subtree), and `/` opens `/search` (`from:`, `to:`, `channel:`, `type:`, `since:`, `until:`).
- **Ant view, credentials & held orders:** selecting an ant shows `ants ant show` beside its animated pixel-art avatar head (`[cli]` `theme` and `animate`), live thread progress, UTC-day spend, tabs (`←`/`→`) for threads (those where it exchanged a message with a human or posted to a channel, not those where only other ants messaged it, as a reply there reaches another ant; `w` filters work the same way), waiting queue (`ants queue`), memories (`ants ant memories`, `u` refreshes), and settings/admin orders (`Enter`/`n` edits `KEY = VALUE` via `ants ant set`, `r` restarts harnesses, `p` toggles pause/resume, `X` pre-fills `/retire ANT`, `a` pre-fills `@ANT`). On the account-key machine, `ants chat` polls pending `ants add --enroll` and `ants renew` requests every 15 s (`c` opens the credentials page to approve/sign with `a` or reject with `r`); on every machine, `o` opens held assistant admin orders (`a` confirms, `r` denies, as `ants assistant confirm`).
- **Direct messages:** selecting a person lists DM threads newest first (`n` starts a new thread), opening sealed messages and titles with the device key (`🔒`; `[sealed]` if pre-enrollment, `[forged]` on verification failure).

### `ants chat` command bar

`Ctrl-K` (or typing `@`, `#`, or `/` in a view) focuses the command bar (`Esc` unfocuses keeping text; `Enter` sends; `Alt-Enter` inserts a newline; `Ctrl-E` opens `$VISUAL`/`$EDITOR`; `Tab` completes `@` users, `#` channels, `/` commands, and `/attach` paths):

- `@ant TEXT` starts a new thread with `ant` (on an open channel thread or a channel's feed, posts there mentioning `ant`); `#channel TEXT` posts to `channel`; plain text replies on the open thread (or posts a new thread on the channel on view, DMs the selected person, else sends to the human's assistant or `messenger`); `//TEXT` sends literal leading `/`.
- Slash commands act on the open or selected thread: `/approve [ID] [--always]`, `/reject [ID]`, `/grant [TEXT]`, `/cancel`, `/answer N|TEXT`, `/done`, `/undone`, `/pin`, `/unpin`, `/mute [DURATION]`, `/unmute`, `/snooze [DURATION]`, `/unsnooze`, `/archive`, `/unarchive`, `/title TEXT`, `/react NAME`, `/goto THREAD|#channel|@user`, `/search QUERY`, `/tree`, `/save [PATH]`, `/tldr`, `/digest [SINCE]`, `/attach PATH`, `/detach`, `/retire ANT`, and `/quit`.

### `ants dash`

`ants dash [--since DUR]` (human creds + TTY, default `24h`) displays active threads (`▶` while busy, `done` when marked), selected thread live progress and history, 10 s colony refresh, and live pending tool requests (`Enter` inspects; `a`/`A`/`r` then `y` confirms `allow_once`/`allow_always`/`reject`; `Tab` switches panes, `R` refreshes, `q`/`Ctrl-C` quits). Records approval presence while open.

### Reactions

`ants react MESSAGE REACTION [--remove]` and MCP `react` store `<reactor>.<message_id>.<reaction>` in `ants_reactions` (30 d TTL; requires hub reachability). Humans write/delete only their own keys and read all reactions across `ants inbox`, `ants thread show`, `ants watch`, `ants chat`, and `-f` followers; reactions never end a wait or mark messages read. Humans may pass a unique message-ID prefix (7 d lookup); ant credentials require full UUIDs and call `ants signer` (or `ants webhook serve` for `list_reactions`, or in-process on unauthenticated servers) over `_INBOX.<ant>.reactions`, scoped strictly to messages the ant reads ([auth.md](auth.md#wire-acls-and-verification-invariants)).
