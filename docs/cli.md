# CLI and terminal UIs

The `ants` binary provides scripting commands, daemon and service subcommands, and interactive terminal interfaces (`ants chat` and `ants dash`).

## Commands

| Command | Description |
|---|---|
| `ants ask [--thread THREAD] [--reply-to MESSAGE \| --forward MESSAGE \| --forward-thread THREAD] [--queue] [--plaintext] [--wait \| -f] [--timeout DUR] [--attach PATH]... [@ant] TEXT \| --file PATH \| --edit` | Send to `@ant`, else to the human's assistant while its [grant](auth.md#assistant-grant) stands, else to `system-messenger`; prints `thread <id>`, `message <id>`, `to <ant>` without `@ant` (`to pa (assistant of alice)`), and `attachment <handle>` per `--attach` file. From a human to `@HUMAN`, seals text and attached files for both humans' devices, or refuses without sendable keys unless `--plaintext` ([auth.md](auth.md#sealed-messages-between-humans)). Human messages automatically steer a running prompt on the same thread, joining its turn where the harness takes steers, else interrupting it and prompting the same session next, ahead of the queue ([config.md](config.md#prompt-limits-and-spending-caps)); `--queue` (with `--thread` or `--reply-to`) leaves the prompt running and waits behind it instead. Warns on stderr if `@ant` is missing from `ants_colony`, `stale`, `signed-out`, `failing`, or provider-limited with no fallback answering. `--reply-to` (a message id, or a unique prefix with human creds, as `ants react` takes; human creds only) replies to that message: on its thread (`--thread` must name the same one), to its author without `@ant` unless the CLI's human wrote it, and quoting its author and a 160-character excerpt (see [Quoted replies](#quoted-replies)). `--forward` (a message id or prefix, as `--reply-to` takes; human creds only) hands that message or post on to `@ant`, else the assistant or `system-messenger`, on a new thread: the text, then optional, is a note before the message quoted with its author and its thread, its attachments are stored again for the recipient, and the new thread links to the source thread as a spin-off does, so the source thread's delegation tree shows it (see [Forwarding](#forwarding)). `--forward-thread` (a thread id, prefix or `last`, as `--thread` takes) hands a thread on the same way by its kept TL;DR, refusing until one is kept (`ants thread tldr` keeps one). |
| `ants inbox [--peek] [--thread THREAD] [--limit N] [-f] [--json] [--activity]`, `ants inbox --unread MESSAGE\|THREAD` | Print unread replies (with message IDs and reactions; an ant's face before its name) and mark read across all devices (`--peek` keeps unread; `-f` streams replies, reactions added/removed to shown messages (human creds; `--json`: `{message, by, reaction, removed}`), `MAX_DELIVERIES` advisories, and, without `--thread`/`--json`, tool requests; records presence without `--thread`). Attachments show as `📎 name (size) handle` lines; `--json` gives each reference with `handle`. Reports of an assistant's acts for the human (on its activity threads, `acts-YYYYMMDD-<human>`) are left out of the listing, marked read (unless `--peek`), and summed up in one line per activity thread (`N assistant activity reports on thread T`, none with `--json`); `--activity`, or `--thread` naming an activity thread, lists them one by one. `--unread` marks unread again across all devices a message to the human and the later ones to the human on its thread, or the latest message to the human on a thread (`unread` seqs in the human's `ants_read` marker). |
| `ants colony [--json]` | List ants after each one-line avatar face such as `(ovo)` in its colour (`live`/`stale`, `idle`/`working`/`paused`/`signed-out`/`failing`/`rate-limited`/`out-of-quota`/`fallback`), daemon/perms versions, harness and `AGENT` (`name@version`), capabilities, `escalate_to`, workdirs, and `PROFILE`, the first 40 characters of the profile the ant wrote of itself on one line (control characters left out), plus notes on moved ants (`ants ant export --move`), version/settings drift, recovery, memory pressure, sense keeping none of an ant's data (`sense_unkept`, with why), and duplicate face/colour warnings. `--json` gives each colony entry whole, `sage`, `profile` (the ant's own words) and `sense_unkept` among its fields, and adds `born`, `avatar`, `color`, `prompts` and `sense` (the sense id) from `ants_identities` (`null` without one), and `seed`: where the face's seed comes from (`avatar` set by a human, `sense`, the record's `id`, or `name` without a record). |
| `ants ant show ANT [--json] [--config FILE]` | Show one ant at a glance, matching the ant view of `ants chat`: colony entry (machine, harness, model, workdir, capabilities, escalation chain, `sage`, version, `whoami`, and the `profile` the ant wrote of itself), active holds (sense keeping none of its data among them, with why), waiting queue, spend that UTC day, latest 10 threads, machine `config.toml` settings (secrets hidden; read afresh via `read_settings` admin order with admin creds, else as last read), shared settings (marked `NOT VERIFIED` with the reason when verification fails), and latest 10 admin orders. |
| `ants ant avatar ANT [--seed S \| --reset] [--color C \| --auto-color]` | Print the ant's pixel-art avatar head (coloured half-blocks on a terminal, else ASCII), face, parts, colour, birth, sense id and where the seed comes from, and growth stage (`callow` < 10 prompts, `worker` ≥ 10, `veteran` with scar ≥ 100, `elder` with crown ≥ 1000). `--seed`/`--reset` and `--color` (12 hue names)/`--auto-color` update `ants_identities` via compare-and-set. Human creds. |
| `ants ant set ANT KEY=VALUE... [--no-wait]` | Change an ant's settings in `config.toml` on its machine, or in its [shared settings](config.md#shared-settings) (`whoami`, `memory`, `capabilities`, `model`, `reasoning_effort`, `context`, `fallback`, `allow`, `escalate_to`, `sage`): reads current values first and sends a `set` admin order expecting those values so concurrent edits fail naming the changed field. `KEY` targets the ant's `[[ant]]` table or shared `harnesses.NAME.*`; `VALUE` is TOML (bare words read as strings, empty removes the field). Waits up to 10 s unless `--no-wait` ([auth.md](auth.md#admin-orders)). Admin device creds. |
| `ants ant pause ANT [--machine M] [--wait DUR]` | Pause an ant via admin order (`paused = true`): stops pulling new prompts while running prompts finish and harnesses stay live ([config.md](config.md#pausing-an-ant)). Waits `--wait` (default `10s`). Admin creds. |
| `ants ant resume ANT [--machine M] [--wait DUR]` | Resume a paused ant via admin order, removing `paused` so queued messages run in turn. Admin creds. |
| `ants ant memories ANT [--json] [--machine M]` | Read an ant's memories via `read_memories` admin order while its daemon is online: core memories (`whoami`, `memory`, `tasks`), read-only size-capped harness `memory_files` ([config.md](config.md#memory-files)), `BD_DB` memories, and the memories view of the ant's provider when it serves one, under `memories of provider NAME` (`provider` with `--json`; a provider failing is noted, not fatal). Built-in sense's shows who the ant has become: its identity (card and experience), a `growth report` counting how its identity grew (threads, sense tool calls that wrote by week, memories, votes, dream findings and verdicts, the vital signs of the last dreams, persona and self-model revisions, relationship records against the people who started its threads, skills, and the thresholds they are judged by), persona with its pending proposal, self-model, relationship records, skills, last dream, and core and top memories, each keyed by id, kind, scope and trust; an ant with no sense data reads `no sense data` ([sense.md](sense.md#what-an-operator-sees-and-configures)). Admin device creds. |
| `ants ant mcp ANT [--json] [--machine M] [--sign-in SERVER [--callback URL]]` | Show the MCP servers of `ANT`'s harness and each one's status (`connected`, `pending`, `needs_auth`, `failed`, `disabled`), tools and source via `read_mcp` admin order while its daemon is online; the daemon opens a probe session of the harness for it. Protocols `claude`, `codex` and `copilot-sdk` report them; ACP harnesses do not. `--sign-in` starts the harness's OAuth sign-in to `SERVER` via `mcp_sign_in` and prints the address to open in a browser; a browser on another machine than the ant's ends on a loopback address that fails to load, which `--callback URL` hands over. The harness stores the credentials; running harnesses may need `ants ant restart ANT`, except open `copilot-sdk` sessions listing the server in `mcp_sign_in` ([config.md](config.md#copilot-sdk-protocol--copilot-sdk)), which are told once it connects ([auth.md](auth.md#admin-orders)). Admin device creds. |
| `ants ant sense-id ANT [--take home \| record] [--config FILE]` | Print the sense id the ant's home here keeps and the one its identity record names; while they differ its daemon refuses to open sense. `--take home` names the home's in the record (compare-and-set), `--take record` has the home keep the record's; the other id's data stay in the log, and the daemon opens sense under the settled id when next used. Refused where data would be lost: `record` while writes wait in the home to be appended to the log, either while the home's sense data await their import. Runs where the config file lists the ant. Human creds. |
| `ants ant export ANT [-o FILE] [--move] [--config FILE] [--no-provider]` | Export an ant to a plain JSON file (default `./ANT.ant`, mode `0600`, never overwritten): identity record, verified shared settings (or config settings with a warning), and home memory files packed between prompts ([config.md](config.md#exporting-and-importing-an-ant)), and the export of the ant's provider when it exports (the built-in sense's: the ant's sense log and skill files under a manifest of SHA-256 hashes, [config.md](config.md#senses-part)), through an `export_provider` admin order to this machine's daemon (admin device creds; failing fails the export, `--no-provider` leaves it out). `--move` marks the ant moved so daemons drain and stop serving it. Human creds. |
| `ants ant import FILE [--as NEW] [--no-provider \| --provider-only] [ants add flags]` | Import an exported ant: create its identity record (refused on name or id collision), append `[[ant]]` to `config.toml` (CLI flags override exported settings), issue a new key, and restore memories into an empty home with no tasks. `--as` renames while keeping id, avatar, and growth. A provider's export in the file goes to the ant's provider through an `import_provider` admin order to this machine's daemon (admin device creds), only for a provider of the same name; sense takes its part in under the same sense id once its hashes and log chain verify, keeping the ant's sense data closed until then. When that fails the import warns why, and `--provider-only` retries that part alone for an ant already imported. `--no-provider` leaves it out. Human creds. |
| `ants ant unseal ANT` | Clear the `moved` mark set by `ants ant export --move` so daemons serve the ant again. Human creds. |
| `ants ant orders ANT [--json]` | List admin orders to `ANT` across machines, oldest first (`pending`, `held`, `applied`, or `refused` with reason; `<human> via <assistant>` for assistant orders) ([auth.md](auth.md#admin-orders)). Human creds. |
| `ants ant restart ANT [--now] [--machine M] [--json]` | Order the serving daemon to restart `ANT`'s harnesses: idle ones stop immediately, working ones after their prompt or cancelled immediately with `--now`; next prompts resume sessions in fresh processes ([auth.md](auth.md#admin-orders)). Admin device creds. |
| `ants ant add NAME --on MACHINE [settings] [--wait DURATION]` | Add an ant remotely by [admin order](auth.md#adding-and-retiring-an-ant-by-order): the machine's daemon generates the key, `ants signer` signs it, credentials and `[[ant]]` are written, and the ant starts. Admin creds; `ants signer` running. |
| `ants ant retire ANT [--machine M] [--wait DURATION]` | Retire any config-listed ant by admin order: table removed, ant drained, key revoked by `ants signer`, credentials deleted, home kept, and leaf uplink shrunk (`X` in `ants chat` ant view). Admin creds; `ants signer` running. |
| `ants ant clone SRC NEW [settings] [--machine M] [--wait DURATION]` | Clone `SRC` to `NEW` on `SRC`'s machine by [admin order](auth.md#cloning-an-ant-by-order): pauses `SRC`, copies home, thread histories, worktrees (`ants/NEW/<thread>` with uncommitted changes), and `[[ant]]` settings, forks or seeds sessions, signs `NEW`'s key via `ants signer`, and resumes `SRC`. Admin creds; `ants signer` running. |
| `ants machines [ANT] [--json]` | List machines recorded in `ants_machines` (machine, host name, version, timestamp, ants) plus the account-key holder `_account`; with `ANT`, list machines serving it, latest first. Human creds. |
| `ants spend [ANT] [--thread THREAD \| --days N] [--json] [--config FILE]` | Report token and cost spend over UTC days (default 7, max 366) or on a thread against local config caps ([config.md](config.md#spend-report)). |
| `ants notes THREAD [--attach PATH]... [TEXT]` | Show thread notes with attachments, or post `TEXT` (with `--attach` files) as the CLI human (resets budget to 8 turns; wakes nobody). |
| `ants react MESSAGE REACTION [--remove]` | Add or remove a reaction (`1–64` of `a-z0-9-`); wakes nobody, marks nothing read, ends no wait. `MESSAGE` is a message id or (for humans) a unique prefix. With ant creds, `ants signer` applies the change for messages the ant reads. |
| `ants answer MESSAGE PICK...` | Answer an ant's `ask_human` questions in one message, a pick for each in order: option `N`, `N,M` (where several may be picked) or (when allowed) typed text, quoted when several questions are asked (`ants answer 0193 2 1,3 'after lunch'`); a lone question takes every word (`ants answer 0193 not before Friday`). Prints `thread <id>` and `message <id>`. Human creds. |
| `ants post [--thread THREAD] [--reply-to MESSAGE] [--queue] [--wait \| -f] [--timeout DUR] [--attach PATH]... CHANNEL TEXT \| --file PATH \| --edit` | Post to `ops` or `'#ops'`; prints `thread <id>`, `message <id>`, and `attachment <handle>` per `--attach` file (`@ant` wakes members, `@human` notifies members, no mention triages). `--reply-to` replies to a message or post on its thread, quoting it, as for `ants ask`; a post being replied to must be in `CHANNEL`, and the mentions in the text still pick whom the post wakes. `--queue` (with `--thread` or `--reply-to`) waits behind a prompt running on the thread rather than interrupting it, as for `ants ask`. |
| `ants channel create \| set \| add \| remove \| list \| delete` | Manage channels (`--member USER,...`, `--messenger ANT`, `--default-messenger`, `--owner ANT`, `--no-owner`, `--description TEXT`, `--no-description`). A description (up to 1000 characters, human credentials only) opens each member ant's new session on a thread of the channel; `list` shows it in a `DESCRIPTION` column when a channel has one. For human members, `list` includes `UNREAD` counts: the posts the human's notify level of the channel counts, `@M` mentions, and the other unread posts apart (`N (@M) +K other`). |
| `ants channel notify CHANNEL [all\|humans\|mentions]` | Show or set the human's notify level of a channel, across all its devices (`ants_notify`): which unread posts count in `ants chat` and `ants channel list`, the others showing apart and dim. `all` counts every post, `humans` (the default) posts by humans and those mentioning the human, `mentions` only those mentioning the human. Mentions still reach the human's inbox at every level. Human credentials only. |
| `ants channel read CHANNEL [--thread THREAD \| --limit N] [--archived] [--peek]` | Print channel posts grouped by thread with attachments, leaving out the human's archived and `auto-archived` threads unless posted on since (`--archived` prints only those); marks printed posts read across human devices unless `--peek`. |
| `ants channel serve` | Run the channel manager (`ants auth channel-manager` creds) to apply owner `manage_channel` requests and an assistant's `describe_channel_for_human`. |
| `ants auth builtin messenger\|sage [--js-domain DOMAIN]` | Issue credentials for `system-messenger` or `system-sage`. Run on the machine holding the [team keys](auth.md). |
| `ants thread list [--ant USER] [--owner HUMAN] [--grep TEXT] [--escalated] [--pinned \| --archived] [--since DUR] [--limit N] [--json]` | List active threads within `--since` (default `24h`, `0` all; limit 50), pinned last, archived and `auto-archived` hidden unless `archived+new`, `done` in STATE. |
| `ants thread show THREAD [--since DUR] [--json] [--no-tools]` | Print a thread's stored messages, posts, notes, escalations, tool requests/decisions, dead letters, attachments, questions/answers, and reactions under a title/done/mark header. Each message is a `● <from> -> <to> · <time> · message <id>` line (its kind, note and answer after the route when there are any) with its text indented under it. Timeline entries follow as `⎿` lines: tool calls as `<time> <ant>  Name(args) · <duration>` (or `failed after <duration>`, `in progress`), rejected or expired tool requests with the tool, request id and outcome (including the decider and assistant when recorded; kind `rejected` in `--json`), and `no reply` lines for turns that sent no reply. `--no-tools` omits the timeline's tool calls and rejections, not stored requests, decisions or `no reply` lines. A quoted reply starts with `↪ replying to <author>: <excerpt>`. |
| `ants thread search [--grep TEXT] [--from USER] [--to USER] [--channel NAME] [--type KIND,...] [--since TIME] [--until TIME] [--limit N] [--json]` | Search stored messages across threads matching all filters (latest `--limit`, default 50, oldest first). |
| `ants thread title THREAD [TEXT...] [--clear]` | Print, set (1–120 chars, shared across humans), or clear a thread title; sealed for both humans' devices on sealed DM threads. |
| `ants thread done \| undone THREAD` | Mark a thread done or clear its done state for every human; a later message, post, or note reopens it. |
| `ants thread pin \| unpin \| archive \| unarchive THREAD` | Pin or archive a thread for the CLI human across devices (mutually exclusive; unarchiving an `auto-archived` thread keeps it another `auto_archive` period). |
| `ants thread tldr THREAD [--new] [--json]` | Print the thread's stored TL;DR while current, else ask `[cli]` `summary_ant` for one (≤ 120 words) and store it ([config.md](config.md#catch-up-summaries)). |
| `ants digest [--since DUR]` | Ask `[cli]` `summary_ant` for a digest of threads active within `--since` (default `24h`, `0` all); stored nowhere. |
| `ants thread mute \| unmute THREAD [--for DUR]` | Mute push notifications for `THREAD` across devices (default `30d`, max `365d`), or unmute ([webhooks.md](webhooks.md#quiet-hours-snooze-and-muted-threads)). |
| `ants trail save FILE [--name NAME]` | Save the [trail](trails.md) of a `.py` file for the colony in `ants_trails`, under its meta's `name` or `--name` (1–64 of `a-z0-9-`; a UUID is refused, as `ants trail show` reads one as a run's id), with the human and time that saved it. The file is checked, not run: it must compile (a syntax error prints the traceback with its line) and start with its literal `meta`. Replaces a saved trail of the same name and says whose it replaced. Human creds. |
| `ants trail list [--json]` | List saved trails with description, phases and source: the colony's (`colony`, saved by whom and when), then this machine's `~/.ants/trails/*.py` that pass the same check, each named by its file name less `.py` as a conductor's daemon finds it (files failing the check, or whose name is no trail name, are skipped with a warning). A local trail sharing a colony trail's name is marked `(the colony's runs)`: the colony's trail is the one a run of that name runs. `--json` prints one object per trail (`source` `colony` or `local`, `shadowed` when marked). |
| `ants trail show NAME\|RUN [--json] [--follow]` | With a trail's name, print its meta, source and script, the colony's before a local one of the same name (and which local file it takes precedence over). With a run's id (a UUID, as `ants trail runs` lists, or a unique start of one when no trail has that name), print the run: trail, conductor, owner, thread and starter, state (and result or error), phase, times, steps and turns spent of its limits, args, the calls waiting on an answer and those queued, and its journal (call, function, ant or capability, label or prompt, `ok:` answer or `error:`). `--json` prints the trail with its script, or the run's record with `pending`, `queued` and `journal`. `--follow` follows the run instead, as `ants trail run --follow` does. A run needs human creds. |
| `ants trail rm NAME` | Remove a trail the colony saved; refused when the colony has none of that name. A local trail stays until its file is deleted. Human creds. |
| `ants trail run NAME\|FILE [--args JSON] [--ant CONDUCTOR] [--thread THREAD] [--steps N] [--at-once N] [--turns N] [--wall DUR] [--yes] [--follow] [--json]` | Start a run of a saved trail (the colony's before a local one of the same name; a local one is sent inline, as the conductor may run on another machine) or of a `.py` file, checked here as `ants trail save` does and sent inline. `--args` is the script's `args` (JSON, at most 64 KiB). The conductor, whose daemon runs the script, defaults to where `ants ask` without `@ant` goes: the human's assistant, else the messenger. The run reports on `--thread` (an id, a unique start of one, or `last`) or a new thread, which the human owns. The limits default to 50 steps, 4 at once, 200 turns and 24h of wall time (stopped time included), at most 500, 16, 2000 and 7d. Prints the trail's meta, conductor and thread, and what the run may spend (steps, at once, turns, wall time, compute per resume of the script), then asks to confirm on a terminal; without one, `--yes` is required. Prints the run's id and thread, or the conductor's refusal (non-zero exit). `--follow` then prints the run's phase, the steps queued, sent, asked again, sent anew, answered or failed, and its state (running, waiting on humans), polling `ants_trail_runs`, until it ends: `done:` and its result with exit 0, or its error or who stopped it with a non-zero exit; interrupting stops the following, not the run. `--json` prints `{"run","conductor","thread"}` (the summary goes to stderr), and with `--follow` the run's record once it ends instead of its steps. Human creds. |
| `ants trail stop RUN` | Stop a run (its id or a unique start of one, as `ants trail runs` lists): its conductor sends no further step and ignores the replies of the steps waited on, and withdraws the steps sent to the conductor itself. Prints the steps still waiting in other ants' queues, each with `ants withdraw ANT MESSAGE` to withdraw it while not started. Refused for a run that ended or was stopped already. Human creds. |
| `ants trail resume RUN [--steps N] [--at-once N] [--turns N] [--wall DUR] [--follow]` | Resume a stopped run, or one failed on a limit, from its stored record: the steps waited on go out anew, on new threads. Limit flags replace those of the run's limits they name (within the same maxima). Refused for a run running, waiting on humans, done or failed otherwise. `--follow` follows it as `ants trail run --follow` does. Human creds. |
| `ants trail runs [--ant CONDUCTOR] [--json]` | List the runs conductors keep in `ants_trail_runs`, oldest first, all conductors' or `CONDUCTOR`'s: run id, trail (`inline` for a script given inline), conductor, owner, state (`running`, `waiting`, `stopped`, `done`, `failed`), phase, steps and turns spent of their limits, started and ended. `--json` prints each run's record without its script. Human creds. |
| `ants attachment get HANDLE [-o PATH]` | Save an attachment to `PATH` or `./name` after verifying size and SHA-256 (never overwrites; opens sealed attachments with the device key; waits up to 60 s for recent outbox chunks) ([transport.md](transport.md#store-and-forward)). |
| `ants assistant enable` / `disable` | Provision or withdraw/retire the CLI human's dedicated assistant ant (`<human>-assistant` by default, locally with the account key or remotely via `--on MACHINE`) ([auth.md](auth.md#dedicated-assistant)). |
| `ants assistant set ANT` / `clear` / `show [HUMAN]` | Designate an existing non-templated ant as assistant, withdraw the grant immediately, or inspect a verified grant ([auth.md](auth.md#assistant-grant)). |
| `ants assistant confirm [ACT] [--deny]` / `allow [RULE...] [--remove \| --clear]` | List, confirm, or deny held assistant tool decisions (`<ant>/<id>`) and admin orders (`<machine>/<ant>/<id>`), or manage device-signed pre-allow rules ([auth.md](auth.md#confirming-an-assistants-acts)). |
| `ants assistant seal on [--key KEY]` / `seal off` / `key ANT` | Enroll or remove the assistant as an encryption device for sealed messages, or print/create an ant's encryption key ([auth.md](auth.md#assistant-as-a-device)). |
| `ants remind set MESSAGE\|THREAD DURATION\|TIME [NOTE...]` / `list [--json]` / `clear MESSAGE\|THREAD` | Set, list (soonest due first), or clear the CLI human's reminders, in the store `/remind` in `ants chat` uses ([command bar](#ants-chat-command-bar)); needs a human's credentials. |
| `ants notify snooze DUR` / `resume` / `status [--json]` | Snooze push notifications (`1s`–`365d`, subject to `bypass`), resume, or inspect active holds and the channels' notify levels other than the default. |
| `ants watch [ANT [THREAD] \| SUBJECT]` | Stream bus traffic (default `ants.>`), escalations/decisions, reactions (human creds), or live harness progress for `ANT`. |
| `ants` / `ants chat [--since DUR] [--compact]` | Full-screen terminal chat UI (`--since` default `7d`; `--compact` draws a two-line tmux pane; bare `ants` opens on a TTY). |
| `ants status [--tmux \| --json]` | Single-line non-TTY summary (3 s read bound): home items by kind, working ants, and UTC-day spend (`--tmux` prints `⚑<items> ◐<working> $<spend>`). |
| `ants dash [--since DUR]` | Interactive TUI for recent threads (default `24h`), live progress, colony, and tool approvals. |
| `ants cancel ANT THREAD` | Cancel the prompt `ANT` runs on `THREAD` (5 s timeout; human creds). |
| `ants queue [ANT] [--json]` / `ants withdraw ANT MESSAGE` | List waiting messages for `ANT` (or all live ants), or withdraw one not started yet or awaiting a retry after a failed attempt or a sign-in/provider-limit hold (human creds; `MESSAGE` may be a channel post waking `ANT`; `W`/`E` in the `ants chat` thread view do too). |
| `ants tools list [-f] [--json]` / `show ID [--json]` | List or inspect pending tool requests (`<ant>/<id>`, unique prefix accepted; `-f` records approval presence); `show` gives what `allow-always` allows, as the harness names it (`always`). |
| `ants tools approve ID [--always] [--rule [--config FILE]]` / `reject ID [--note TEXT]` | Decide a pending tool request; `--rule` appends the exact allow rule to `config.toml` and reloads the daemon; `--note` sends TEXT to the ant on the request's thread once the rejection is stored (as any human message there, it steers the running prompt and renews the turn budget), and not at all when the rejection is refused, which exits non-zero naming who decided. |
| `ants dead list` / `replay SEQ` / `drop SEQ` / `watch [--metrics ADDR]` | Inspect, replay, or drop dead letters; `watch` converts `MAX_DELIVERIES` advisories into dead letters. |

### Thread and message identifiers

`THREAD` in `ask`, `inbox`, `post`, `notes`, `thread show`, `thread title`, `thread pin`/`unpin`/`archive`/`unarchive`, `thread done`/`undone`, `thread mute`/`unmute`, `cancel`, `watch`, `spend --thread`, and `channel read --thread` accepts a hyphenated UUID (used without lookup), a unique prefix (or non-UUID thread ID), or `last` (latest thread the human sent or received on). Prefix lookup (human creds only) checks the human's own threads from the last 7 d first, then all threads in the last 7 d (bounded to `[-5m, +10m]` around the timestamp encoded in a UUIDv7 prefix); exact matches win, and ambiguous or missing prefixes list candidates (id, time, title where readable, route, and first line of the latest message).

### Quoted replies

A quoted reply (`ants ask --reply-to`, `ants post --reply-to`, or `>` in the `ants chat` thread view) names the message it replies to in `in_reply_to` and carries `quote`: that message's author and its text with whitespace collapsed, cut at 160 characters with `…`. The daemon starts the prompt for it with `[ants] In reply to <author>: "<excerpt>"`, since the ant may not hold the message (another ant wrote it, or it is from an earlier session). `ants thread show` and the thread view show `↪ replying to <author>: <excerpt>` above its text. Between humans, the quote is sealed with the text. A sealed message's excerpt never goes in the clear: a reply quoting one that is not sealed itself (to an ant, a channel post, or `--plaintext`) carries only the author, shown as `↪ replying to <author>` and prompted as `[ants] In reply to a sealed message from <author>.`. The CLI reads the message back with the human's credentials to quote it (a message kept over the last 7 days), so a sealed message that does not open on the device cannot be quoted.

### Forwarding

`ants ask --forward MESSAGE`, and `f` or `/forward @ant [TEXT]` in the `ants chat` thread view, hand a message to another user on a new thread; `ants ask --forward-thread THREAD`, and `f` on a home item or a work thread, hand a thread by its kept TL;DR. The new thread's first message holds the note, if any, then `Forwarded from <author> on thread <id>, <time> UTC:` and the message's text quoted line by line, with a `📎 <name> (attached)` line per attachment; the attachments are read with the human's credentials (opened when sealed on a message that opens on the device) and stored again under the new message, for its recipient. With no message selected in the thread view, or a thread selected elsewhere, `/forward` carries the thread's TL;DR instead (`Forwarded thread <id>, its TL;DR by <ant>, <time> UTC:`), refusing until one is kept (`S` or `/tldr` asks for one). The message links to the source thread (`origin_thread`), as a message an ant spins off a thread does, so `ants chat`'s delegation tree of the source thread shows the new thread, labelled `forwarded:` where a thread an ant spun off shows `spin-off:`. The recipient gets only what is forwarded: no access to the source thread or its other messages comes with it.

## Identity, setup, completions and doctor

- **Connection & identity:** every command accepts `--nats`, `--creds`, and `--js-domain`, falling back to `[cli]` then top-level keys in `ANTS_CONFIG` (`~/.ants/config.toml`), except `ants daemon` and `ants add` (which read top-level config directly). NATS URLs containing credentials or tokens are rejected. Connecting with human credentials ensures `ants_humans` contains `<name>` (`human` needs no entry) and runs an `ants init` pass creating missing objects. Ant credentials skip `ants_humans`, warn, refuse `ants inbox`, and leave `--wait`/`-f` replies unread.
- **`ants setup`:** without `--harness` and an existing config file, chooses the harness of a new config by looking up each built-in's command on `PATH` (no handshake): a single installed harness is picked and reported, multiple are offered in a numbered terminal prompt (failing without a TTY), and none installed fails with install and sign-in commands ([config.md](config.md#choosing-a-harness-in-ants-setup)). Setup then idempotently writes `~/.config/ants/nats.conf` (JetStream in `~/.ants/jetstream`, skipped for non-loopback `--nats` or existing `leaf.conf`), downloads the pinned nats-server into `~/.ants/bin` when the service or `--managed-nats` needs one and neither `--nats-server` nor a nats-server beside `ants`, in `~/.ants/bin` or on `PATH` is found ([operations.md](operations.md#bundled-nats-server)), installs/starts `ants.nats` / `ants-nats`, runs `ants init`, creates/appends `~/.ants/config.toml`, runs `ants harness check`, issues host credentials when ants have credentials and team keys are local ([auth.md](auth.md#machine-host-credentials)), installs/starts/reloads `ants.daemon` / `ants-daemon`, installs shell completions, and runs `ants doctor --no-harness` (`--dry-run` previews without changes). `--managed-nats` (loopback `--nats` only) installs no NATS service: a new config file gets a [`[nats_server]`](config.md#managed-nats-server) table naming `leaf.conf` when present, else `nats.conf` (with `command` from `--nats-server`), the daemon service is installed or restarted, and `ants init` runs once the daemon's server listens (`--no-services` prints `ants daemon --config FILE` instead). It fails while an `ants.nats` / `ants-nats` unit is installed for that configuration, printing the commands that remove it, or, for a new config file, while a server listens on the address already; an existing config file is not edited, and without the table its step fails naming the line to add and the daemon restart to run.
- **Shell completions:** `ants completions --install` writes to `~/.local/share/bash-completion/completions/ants`, `~/.local/share/zsh/site-functions/_ants` (add to `fpath` before `compinit`), or `~/.config/fish/completions/ants.fish` (`XDG_DATA_HOME`/`XDG_CONFIG_HOME` honoured). Dynamic lookups (`ANTS_COMPLETE`, 2 s timeout, silent on error, skipped for OS-keystore seeds) complete `@ant` / ant names, channels, `last` + recent 7 d threads (with thread `title`, else latest line), the latest 50 messages to or from the CLI human over 7 d matching the typed prefix and suggested reactions on `ants react`, pending tool requests, and dead-letter sequences.
- **`ants doctor`:** read-only end-to-end check (`ok`, `warn`, `fail`, `skip`, with `fix` commands; 5 s per request, 10 s per network check, 60 s per harness handshake). Checks `config`, CLI `credentials` + OS `credentials key` + device `credentials xkey`, `server` (failing below `nats-server` 2.15) + `jetstream`, `hub` objects, `consumers` (`≥ 80%` of `max_consumers`), team `versions` + cross-machine `harness versions` + `shared settings` drift + `avatars` + `moved ants`, JetStream `storage`, `host credentials` and `machine name`, `sense data` (failing where sense keeps none of the data of the ants using it: no host credentials on a server with authentication, naming `ants auth host MACHINE` or `provider = "none"`, or a live colony entry on the machine saying why (`sense_unkept`), as of an ant `ants daemon --ant` serves from flags alone), per-ant `credentials` / `harness` / shared git `workdir` / `reactions` / `tool permissions` / `reviews` (a sage on a harness running its tools unasked with no `review`) / `sense chain` (the chain of the ant's sense event log as its daemon last verified it, kept in the ant's home in `.sense/chain.json`, failing at a break: [architecture.md](architecture.md#stores-and-subjects)) / `sense size` (the bytes of that log as last read, warning over 32 MiB), `hub resolver` (`full` resolver) + `team keys backup`, `leaf` / `leaf uplink` / `leaf system uplink` / `leaf node` / `outbox`, installed `daemon` / `leaf node` / `hub` / `webhook` services (the configuration `[nats_server]` names checked as run by the daemon service, failing when an `ants.nats` / `ants-nats` unit runs it too: [operations.md](operations.md#managed-nats-server)), `webhooks.toml` secrets (`0600`) / `exec` commands / `public_url` `/_approval` probe, and installed `devtunnel` / `bridge` services, tokens, and reachability, and, with the config file's `auto_update` on, whether a newer release is out (`update`: [operations.md](operations.md#automatic-updates)).

## Composing and waiting

- **Input:** `ants ask` and `ants post` take trailing words joined by spaces, `--file PATH` (`--file -` reads stdin; preserves internal formatting, strips BOM and trailing newlines), or `--edit` (`$VISUAL` -> `$EDITOR` -> `vi`/`notepad` on a `0600` temp file; empty/blank messages abort).
- **Attachments:** `--attach PATH` (repeatable; `ants ask`, `ants post`, and `ants notes` with `TEXT`) attaches up to 8 regular files of at most 8 MiB each, named by base name and typed by extension (`application/octet-stream` otherwise). Files are stored in `ants_files` before sending; any failure sends nothing. Each attachment gets a handle `<sender>.<inbox|notes|chan>.<target>.<id>` accepted by `ants attachment get`.
- **Sealed messages:** messages between two humans are sealed end to end for their devices' keys in `ants_devices` and any device-enrolled assistant (`ants assistant seal on`), unless `--plaintext` is set. Readers print opened text, looking up newly enrolled sending devices on demand, else `[sealed]` (no key for this device) or `[forged]` (decryption/sender failure); `--grep` matches opened text only, and `ants watch` and dead letters show `[sealed, N bytes]` ([auth.md](auth.md#sealed-messages-between-humans)).
- **Waiting:** `--wait` prints the first reply and exits `0` (`--timeout` exits `1` on timeout; Ctrl-C exits `130`); `-f`/`--follow` streams replies until `--timeout` or Ctrl-C (`0`), marking printed replies read, plus live reaction changes on the sent message and printed replies (human creds). On a terminal with human credentials, stderr displays an in-place status line (`not served`, `queued behind N`, `working`, `thinking`, `writing`, `running <tool>`, `waiting for approval` with `ants tools approve <ant>/<id>`, `harness signed out`).

## Threads, search, titles, done states and marks

`ants thread list`, `show`, and `search` read `ANTS` with human credentials via batched direct gets (`$JS.API.DIRECT.GET.ANTS`, 256 messages/request), consuming and marking read nothing. Entry kinds: `message`, `escalation`, `mention`, `post`, `note`, `approval`, `decision`, `dead` (subject mismatches marked `(forged)`).

- **Search (`ants thread search`):** combines `--from`, `--to`, `--channel`, `--type`, `--grep` (case-insensitive), `--since` (inclusive, default 24 h before `--until`), `--until` (exclusive, default now; accepts durations, RFC 3339, or UTC `YYYY-MM-DD[ HH:MM]`), and `--limit` (default 50). `--from`, `--to`, and `--type` prune scanned subjects server-side.
- **Titles (`ants thread title`):** 1–120 trimmed single-line chars stored at `title.<thread>` in `ants_threads`, shared across humans and shown in `thread list`, `thread show`, `ants chat`, and tab completion. An ant's suggested title (`suggest_thread_title`, carried on its reply) is stored by the next human `ants thread list` or `thread show` via CAS only if `title.<thread>` has no entry and no delete marker (`(suggested by <ant>)`). On threads carrying sealed messages between two humans, `ants thread title` seals the title for both humans' devices (`[sealed]` elsewhere) and ignores ant suggestions ([auth.md](auth.md#sealed-messages-between-humans)).
- **Done (`ants thread done|undone`):** shared state at `done.<thread>` in `ants_threads` (`ThreadDone {thread_id, by, at, after}`); changes no ant's work, reply, or notification, but ends the [escalation reminders](architecture.md) of an escalation marked done after, and the daemon of each ant holding a session of the thread tells the ant's provider (`thread_done`, [lifecycle events](architecture.md#lifecycle-events)). Any message, channel post, or note stored above `after` reopens the thread at read time without a write (tool requests, decisions, and dead letters do not). `ants thread undone` writes a 30-day delete marker so [review packets](sense.md#dreams) can distinguish an explicit undo from a thread never marked done.
- **Pins & archives (`ants thread pin|unpin|archive|unarchive`):** per-human CAS state at `marks.<human>` in `ants_threads` (mutually exclusive). Pinned threads sort last and survive `--limit`; archived threads hide from `ants thread list`, `ants dash`, `ants channel read`, and `ants chat`'s work, the `all` tab of channel views (their `archived` tab lists them), DMs and their unread counts (as do `ants channel list`'s) until new messages arrive (`archived+new`).
- **Auto-archive (`auto_archive` in `[cli]`):** off by default; with e.g. `auto_archive = "14d"`, an unpinned, unarchived thread with no entry stored for that span counts at read time as `auto-archived` (`auto_archived` in `--json`) and hides like an archived thread until a new entry arrives. `ants thread unarchive` stores a `kept` timestamp in `marks.<human>` for one more `auto_archive` idle period.
- **TL;DRs and digests (`ants thread tldr`, `ants digest`):** requested from `[cli]` `summary_ant` on dedicated summary threads hidden from thread lists, the inbox, and push notifications; see [config.md](config.md#catch-up-summaries).
- **Pruning:** `ants thread list` prunes marks, titles, TL;DRs, and done states of threads with no message remaining in `ANTS` (30 d retention + 30 d outbox grace), using CAS and revision-conditioned deletes with 1 s TTL delete markers.

## Terminal UIs and reactions

### `ants chat`

`ants chat [--since DUR] [--compact]` (also bare `ants` on a TTY; human creds, default `--since 7d`) opens the full-screen terminal chat UI. Without a TTY it exits naming the scripting commands; with no server reachable within 5 s it points to `ants setup` and `ants login`. Updates arrive live from `ANTS`, status events, and `ants_colony`, recording inbox and approval presence while open. `Tab` switches between navigation and the active view, `Esc` goes back, `R` refreshes, `?` opens the help, and `/quit` quits at once. `q` quits only with the command bar empty (in a conversation while writing, it is written), and a `q` within a second of one closing the help, the notices, the digest or a tool request does nothing. `Ctrl-C` closes what is open (the help, the notices, the digest, a tool request, a prompt in the footer, the bar's completion list, a thread's find, a draft or confirmation in the view), else empties the command bar into its history, as `Esc` twice does, else asks in the footer for a second `Ctrl-C` within a second and quits on it. The help lists the keys of the view on screen (on an ant, of each of its panes; a tool request shown in full instead), then those of the command bar, then those acting everywhere, each wrapped to the width and dim with why when it cannot act now; `↑↓`/`PgUp`/`PgDn` scroll it and `Esc`, `q` or `?` closes it, other keys doing nothing. The footer shows, most important first, the keys of the view and of everywhere that can act now (none of `a`/`A`/`r`/`n` without a pending tool request), as many as fit whole in the width, and always ends in `? help`. A notice shows there for 15 s, cut at the width with `…`, as the command bar's status line is; an error begins with `✗` besides its colour and stays, wrapped over three lines at most, until a key is pressed. `N` lists the notices of the run, the latest first, each in full with its local time (`↑↓`/`PgUp`/`PgDn` scroll; `Esc`, `q` or `N` closes). While a thread's find (`Ctrl-F`) is active, `n` and `N` step through its matches instead. In a thread, a channel's feed and a DM, a printable key focuses the command bar and is written there (`?` on an empty bar shows the help instead), and `Enter` on an empty bar does the view's `Enter`; `↑` selects the latest message or post (in a thread, the one selected before writing, if any), the view's single keys then act on it as listed below, and `i`, `End` or `Esc` come back to writing; a thread scrolls while writing with `PgUp`/`PgDn` and `Ctrl-Home`/`Ctrl-End`. The footer and the help show which holds: while writing, `a-z write` and `↑ select` lead, and the help dims the letter keys. Log lines are held from the start, before connecting, and written once `ants chat` ends. With no thread read, home lists what can be typed: `@ant` and a text to ask an ant, `#channel` and a text to post, `Ctrl-K` and a text for the assistant or the messenger, and `?` for the keys. In the lists and the thread view, a bar at the left of each of its lines marks the selected item (coloured in the focused view, dim otherwise; without colour under `NO_COLOR`) and its first line is bold; tables and tabs mark the selected row in reverse video.

- **Navigation & header:** the header shows the human, server, the place shown (on a thread, its channels and title) and connection state. Under 100 columns the sidebar shows only while it has the focus, over the view: `Tab` brings it, and `Tab`, `Enter` or `Esc` leave it. `Ctrl-O` folds or shows the sidebar at any width, and `Ctrl-\` the thread view's side panel; pressed again where the width would have it so, each follows the width again. The choice is kept in `chat-state.json` on the device. The sidebar lists **home** (count of items waiting on the human), **assistant activity** (once there is any: the human's activity threads, one per UTC day, gathering the reports of an assistant's acts for the human; they stay out of home, work and its counts), **work** (all other threads plus counts by state: `waiting on me`, `working`, `waiting on ant`, `stuck`, `idle`, `done`, rows that show under work only while work or one of them is selected, folded otherwise), **channels** (bold unread counts of the posts the channel's notify level counts, by default those by humans or mentioning the human, `@N` mentions, and a dim `·K` count of the other unread posts), **ants** (`●` live, `◐` busy, `◌` limited/fallback, `‖` paused, `✕` signed out/failing, `○` stale, with each ant's coloured face unless `NO_COLOR` is set), and **people** (`●` online via `ants_presence`, `○` away, `·` unknown, with unread DM counts). `Ctrl-T` (the bar focused too) shows the next channel, person or thread with something unread after the one shown.
- **Home triage & `--compact`:** home's summary line counts changes since the previous session on the device (`chat-state.json` beside `config.toml`, else 24 h; the file also keeps the thread view's `T` choice, each channel view's tab, and what `Ctrl-O` and `Ctrl-\` fold) and UTC-day spend; `s` opens/refreshes a digest overlay (`j`/`k` scroll). Below it, home orders items waiting on the human, one row per thread under its most pressing reason with badges for the others (e.g. `question · stuck · 2 mentions`; keys act on the top reason), most pressing first and oldest first within each kind: pending tool requests, unanswered `ask_human` questions, stuck threads, unread human DMs, unread mentions, due reminders (the note and thread title, else a `reminder` badge on a thread with a more pressing reason; `Enter` opens the message reminded of), and finished threads whose answer is unread (read on any device, a finished thread leaves home and stays in work; `u` marking its answer unread brings it back). Home opens on its top item and keeps the top item selected as items arrive until a key moves the selection, which from then on stays with its item. Keys act inline: the selected tool card, the one the keys answer, shows what its request asks, wrapped over at most six lines, fewer (none at all) where the screen is too short to show them over the card's other lines and keys (an execute request's command once, as text); ### Terminal interaction

`ants chat` enables mouse reporting by default (`[cli] mouse = false` disables it). The wheel scrolls the
conversation, list or overlay under the pointer one line at a time. Click a row, navigation entry, state tab,
question option or completion to select it; click again to open or apply it. Hold Shift for native terminal text
selection, or Option in iTerm2. Mouse reporting stops on exit, panic and editor or pager handover.

The terminal reports focus while chat runs. A new item on home rings the bell once while unfocused.
`[cli] notify = "terminal"` uses terminal notifications (OSC 99 on kitty, OSC 777 on rxvt, OSC 9 otherwise);
`notify = "off"` disables these announcements. The tab title shows `ants (N)`, with the number of home items,
and the previous title is restored on leaving. Device presence and push-sink suppression stay unchanged.

With a message selected, `y` copies through the first available local `pbcopy`, `wl-copy`, `xclip` or `clip.exe`.
Over SSH, or without a clipboard executable, it sends OSC 52 instead. The notice identifies the transport;
command failures are errors, and OSC 52 reports an unacknowledged request rather than confirmed clipboard contents.
A message containing code blocks opens a chooser: the whole message first, followed by each code block.
Links and bare HTTP(S) URLs become OSC 8 hyperlinks on known supporting terminals, including iTerm2, kitty,
WezTerm, foot, Ghostty, VTE and Windows Terminal; terminal-specific link-opening modifiers still apply.

On Unix, `Ctrl-Z` restores the terminal and suspends chat; `fg` resumes and redraws it. Mouse and focus reporting
are disabled while an external editor, pager or shell owns the terminal.

### `ants chat` command bar

An empty command bar says what `Enter` does with a text alone in the view on screen. `Ctrl-K` or `/` in a view, on an empty bar, opens the palette: one list of the slash commands with their arguments, the keys of the view on screen with what each does, and the places: channels, ants, people and the threads work lists by title, those with something unread or waiting first, narrowed as typed after the `/` with no sigil (`/ops` lists `#ops`), those that cannot act here dim with the reason (`/archive (no thread open or selected)`); `↑↓` pick, `Enter` runs a command needing no argument, presses the key (on a dim one, says why) or shows the place, `Tab` (or `Enter` on a command taking one) completes the command in the bar, `Esc` closes it, and `Backspace` on the lone `/` leaves an empty bar to write in. An unknown or malformed slash command, besides its error, opens the palette on the commands its name matches, else on all of them, until the text is edited (`Esc` closes it, keeping the text). `Ctrl-F` outside a thread view opens the bar on `/search `. With a text in the bar, `Ctrl-K` or `/` focuses it as typing `@` or `#` in a view does (`Esc` unfocuses keeping text; `Enter` sends; `Ctrl-J`, or `Enter` right after a `\` (which it removes), inserts a newline, as do `Shift-Enter` and `Alt-Enter` where the terminal tells them from `Enter`: `ants chat` asks a terminal that answers the kitty keyboard protocol's query to disambiguate keys while the screen shows, taking it back on leaving, on a panic and while the editor runs; a paste goes in whole, its line breaks newlines, focusing the bar unless a prompt or another text input takes it on one line, and one of over 800 characters or 3 lines shows as `[Pasted text #1 +120 lines]`, moved over and deleted as one character and sent in full; one over 64 KiB is attached as `paste-1.txt`, and image files dropped on the terminal (pasted as their absolute paths) are attached, as `/attach` does; it edits as a shell line: `Ctrl-A`/`Ctrl-E` (or `Home`/`End`) go to the ends of the line, `Ctrl-K`/`Ctrl-U` delete to them (at an end, the line break), `Ctrl-W` deletes the word before the cursor up to a space and `Alt-Backspace`/`Alt-D` the word before or after it, `Ctrl-Y` puts back what was deleted last (a paste as its placeholder), `Alt-B`/`Alt-F` (or `Ctrl-`/`Alt-` arrows) move by words, `Up`/`Down` move between the lines of a text of several, lines wrap at words, and another `Alt-` key does nothing (every other text input of `ants chat` edits its one line with the same keys: the snooze and reminder prompts, the reaction picker, a question's typed answer, a setting's change, the MCP address handed over and the rows of a channel's members editor); `Ctrl-G` or `Ctrl-X Ctrl-E` opens the text in `$VISUAL`/`$EDITOR`; `Tab` completes `@` users, `#` channels, and `/attach` paths):

- `@ant TEXT` starts a new thread with `ant` (on an open channel thread or a channel's feed, posts there mentioning `ant`); `#channel TEXT` posts to `channel`; plain text replies on the open thread (or posts a new thread on the channel on view, DMs the selected person, else sends to the human's assistant or `system-messenger`); `//TEXT` sends literal leading `/`.
- Slash commands act on the open or selected thread: `/approve [ID] [--always]`, `/reject [ID]`, `/grant [TEXT]`, `/cancel`, `/later TEXT` (reply on the open thread, waiting behind the prompt running there as `ants ask --queue` does), `/answer PICK...` (the questions of the card the keys answer, a pick for each as `ants answer` takes them), `/done`, `/undone`, `/pin`, `/unpin`, `/mute [DURATION]`, `/unmute`, `/notify all|humans|mentions` (the notify level of the channel on view, or of the open channel thread's channel), `/snooze [DURATION]`, `/unsnooze`, `/remind DURATION|TIME [NOTE]`, `/unremind`, `/archive`, `/unarchive`, `/title TEXT`, `/react NAME`, `/goto THREAD|#channel|@user`, `/search QUERY`, `/tree`, `/forward @ant [TEXT]`, `/save [PATH]`, `/tldr`, `/digest [SINCE]`, `/attach PATH`, `/detach`, `/retire ANT`, and `/quit`.
- **Reminders (`/remind`, `b`):** `/remind 2h check the deploy`, `/remind 09:30` (the next such time on the local clock) or `/remind 2025-07-01T09:00 NOTE` reminds of the selected message in the thread view, else of the thread; `b` asks for the same in the command bar. One reminder per thread is stored per human at `reminders.<human>` in `ants_threads` (CAS, setting another replaces it). Once due, it shows as a `reminder` home item on all the human's devices, and `ants webhook serve` pushes it once ([webhooks.md](webhooks.md#quiet-hours-snooze-and-muted-threads)); `d` on the item or `/unremind` clears it. Outside `ants chat`, `ants remind set|list|clear` does the same: `ants remind set 0193 2h check the deploy` reminds of message `0193…` (else thread `0193…`), and `ants remind list --json` prints one JSON reminder per line (with `thread`, `is_due` and the thread's `title`).
- **Title and drafts:** the bar's title says what `Enter` does with the text as it stands, the routing above applied to it: `reply to dev-b on "deploy the site"`, `new thread in #ops`, `post in #ops on "TITLE"`, `to bob on a new thread, sealed` (a human other than oneself), `to the assistant or the messenger on a new thread`, `run /done`; an `@user` or `#channel` typed first changes it as typed, and `Enter` sends where the title said. The bar's text is the draft of the conversation it was typed in (a thread, a channel's feed, a person's DMs, or none): another view shows its own draft, back in the conversation the draft is in the bar again, and the nav, the work lists, home and a channel's feed mark the conversations holding a draft with `✎`. A send that fails comes back as the draft of the conversation it was typed in.
- **History:** in the focused bar, `Ctrl-P` and `Ctrl-N` recall the texts sent from the bar, latest first (`Ctrl-N` past the latest puts back the text typed), and `Ctrl-R` searches them, latest first and whatever the case: typing narrows the search, `Ctrl-R` again goes to an earlier match, `Enter` takes the text found into the bar without sending it, `Esc` or `Ctrl-G` puts back the text before, and any other key takes the text found and acts. `Esc` twice within a second on a bar holding text empties it into the history. The latest 200 texts and the drafts of the conversations are kept on the device in `chat-bar.json` beside `chat-state.json`, readable by its owner only, and come back in the next `ants chat`. A text or draft addressed to another human (in a DM, on a thread outside channels with another human on it or not read yet, or mentioning one with `@`), which goes sealed, and a slash command acting on such a thread (the one open or selected, any thread when not known, as for a draft of home kept while away), is kept for the run only and never written to disk.

### `ants dash`

`ants dash [--since DUR]` (human creds + TTY, default `24h`) displays active threads (`▶` while busy, `done` when marked), selected thread live progress and history, 10 s colony refresh, and live pending tool requests (`Enter` inspects, naming what `allow_always` allows as the harness does; there `a`/`A`/`r` decide `allow_once`/`allow_always`/`reject` at once, a note with the rejection being `ants chat`'s `n` or `ants tools reject --note`; `Tab` switches panes, `R` refreshes, `q`/`Ctrl-C` quits). Records approval presence while open.

### Reactions

`ants react MESSAGE REACTION [--remove]` and MCP `react` store `<reactor>.<message_id>.<reaction>` in `ants_reactions` (30 d TTL; requires hub reachability). Humans write/delete only their own keys and read all reactions across `ants inbox`, `ants thread show`, `ants watch`, `ants chat`, and `-f` followers; reactions never end a wait or mark messages read. Humans may pass a unique message-ID prefix (7 d lookup); ant credentials require full UUIDs and call `ants signer` (or `ants webhook serve` for `list_reactions`, or in-process on unauthenticated servers) over `_INBOX.<ant>.reactions`, scoped strictly to messages the ant reads ([auth.md](auth.md#wire-acls-and-verification-invariants)).
